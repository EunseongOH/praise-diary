# 디자인시스템 비교 및 적용 결정 (2026-11-21)

브랜드 스타일을 특정 디자인시스템에서 그대로 복제하지 않는다. **문제별로 검증된 설계 원칙을 가져온다.** 실제 컴포넌트 코드는 이 프로젝트의 작은 공통 컴포넌트로 구현하고, 앱인토스 배포 직전 공식 SDK·호환성을 재점검한다.

| 참고 시스템 | 유용한 부분 | 우리 서비스에서 채택 | 채택하지 않는 것 |
|---|---|---|---|
| [Toss TDS Mobile](https://tossmini-docs.toss.im/tds-mobile/) | 버튼/텍스트필드/세그먼트/토스트/시트, 모바일 터치와 상태 | 작성 CTA, 날짜 선택, 저장·삭제 피드백의 명료성 | 토스 금융 서비스 화면을 그대로 복제한 시각 스타일 |
| [Karrot SEED](https://v2.seed-design.io/component/) | 담백한 텍스트 버튼, 스위치, 다이얼로그, 작은 메뉴 행 | 일기/설정의 친근한 낮은 위계, 정확한 터치 타깃 | 빈 공간마다 배지·아이콘을 늘리는 구성 |
| [Shopify Polaris](https://shopify.dev/docs/api/polaris) | 정보 구조, 상태·오류·빈 화면, 동작의 명시성 | 빈 기록·저장 실패·삭제 확인을 사용자 행동 중심으로 | 관리 대시보드형 카드/테이블 중심 디자인 |
| [Material Design 3](https://m3.material.io/) | 상태별 피드백, 키보드, 포커스, 모션 감소, 내비게이션 | 접근성 및 선택/키보드/디바이스 변화 고려 | 무거운 시스템 룩과 불필요한 떠 있는 버튼 |
| [unslop](https://github.com/heydamir/unslop/tree/main/skills/unslop) | AI스러운 반복 패턴 진단 | 시각적 위계·반복 카드·아이콘·그라데이션 최종 품질 감사 | 스킬 규칙의 기계적인 적용/아무 화면에나 효과 추가 |

**타이포:** 한국어 기본 시스템 글꼴, 상단 제목과 본문 간 2~3단계 정도. **색:** 부드러운 종이 배경, 잉크색 텍스트와 절제된 강조색. 월간 그래픽 자체의 팔레트가 계절성을 담당.

**기술 선택:** TDS API 종속 없이 우선 React UI 라이브러리를 만들고 실제 앱인토스 빌드 단계에서 TDS 컴포넌트 대체/래핑을 검증. 코드/UX 명세·디자인 시스템 일치성 유지.
