# 서비스 전체 팝업 정책 (v0.13)

모든 신규 화면, 기존 기능 수정, 인터랙티브 검수판에 적용한다. 사용자에게 제공되는 서비스 자체의 팝업은 반드시 공통 디자인 시스템 컴포넌트로 구현한다.

- 선택: CompactSelect, 공통 메뉴 표면 및 키보드·초점 동작. OS 기본 select/datalist 사용 금지.
- 확인/경고/입력: 공통 Dialog, 필드, Toast. alert/confirm/prompt 사용 금지.
- 날짜/시간/색상 등: 공통 스타일 기반 피커. 브라우저 기본 피커 호출 금지. 파일·권한 등 OS에서만 가능한 시스템 동작은 명시적 검토 필요.
- 설명: 인앱 도움말 또는 툴팁. 브라우저 title 툴팁 금지.
- 검증: 폼 noValidate 및 인앱 오류 텍스트, reportValidity 사용 금지.
- 상태 변화는 동일한 레이아웃 유지. 선택 토글에 체크 추가하지 않기. 좁은 화면에서 열 전체 이동을 방지하고 내부 텍스트 줄바꿈을 허용한다.
- 접근성: 키보드, Escape, 바깥 클릭, 포커스 복귀, aria-expanded/pressed/selected, 충분한 터치 영역을 검수한다. 모바일 키보드, OS 권한창, 보조기술, 브라우저 자체 기능은 서비스 UI가 아니며 억제하지 않는다.

검수 게이트: npm run check:popups (src 전체 정적 검사), npm run check (포함), npm run test:e2e (실제 동작). 새로운 팝업을 추가할 때는 해당 화면의 E2E를 추가하고 검수판에도 실제 공통 팝업 외형/행동을 재현한다. 정적 검사는 동적으로 생성되는 모든 형태를 보장하지 않으므로 브라우저 검수를 병행한다. 이전 역사적 시안은 당시 기록으로 보존하며 재사용 전에 현재 규칙을 적용한다.
