# 다정록 · 꺼내보기 V8 / 오늘의 마음 덧붙이기
2026-11-26 · 디자인 검토용 인터랙티브 프로토타입

## 1. 확정 범위
- [확정] 꺼내보기는 여러 기록을 빠르게 소비하는 기능이 아니라, 과거의 일기 한 편을 다시 만나 위로받는 경험이다.
- [확정] A 둥근 기억병, A1 부드러운 말림, V5 안쪽 풀림, V7-B 부드러운 확산 반사, V7-1 둥근 천연 코르크, B 나란히 쌓인 구도. 기존 2.7초 모션과 4:3 원지 유지. 감상 중 다른 기록 꺼내기 CTA 없음. 닫으면 이미 닫힌 병으로 복귀하며 역재생하지 않는다.
- [확정] '오늘의 마음 덧붙이기' MVP 포함. 같은 종이 안에 이어 쓰고, 원문과 별도 데이터로 관리. 꺼내보기·달력·전체 기록에서 같은 일기에 덧붙일 수 있다.
- [제안/구현] 원문 감상 화면 상단 X만 표시(직접 진입은 이전 버튼+칭찬일기), 하단 탭 숨김. 종이 바깥 아래 텍스트 CTA → 종이 내부 인라인 작성. 여러 마음은 생성 시각 오름차순, 날짜로 구분. 본문은 16px/1.75/400 Pretendard, 날짜 13px, 원문과 추가 기록 구분선·간격 24px. UI A 열린 입력을 기본으로 하고 B 줄 있는 종이, C 입력 영역 경계 비교. 저장 후 읽기 유지. 수정·삭제는 각 마음의 더보기에서 제공.
- [제안/구현] 보이는 쪽지: 원본 0개=0장, 1~2개=1장, 3~9개=3장, 10개 이상=5장. 현재 원본 수를 기준으로 함. 최초 10개에서 해제, 일부 삭제로 재잠금하지 않음. 시각 쪽지 수와 실제 추첨은 독립. 추첨은 직전 원본 제외(두 개 이상일 때), 한 개만 남으면 재등장 가능. 기록 소비 없음.
- [보류] 포인트/병 꾸미기, 서체 개인화, 실제 아트워크의 최종 QA. 이번 V8의 홈·도감은 연동 확인용이며 디자인 확정본이 아니다.

## 3. 공통 컴포넌트 계약 (React 통합 후보)
- `DiaryContent(entry, reflections, mode)`: 날짜, 선택 제목, 줄바꿈 원문, 마음 목록. 감상/직접 조회 공통. 읽기 영역은 기본 4:3 최소 높이, 내용이 길면 아래로 확장.
- `ReflectionComposer(entryId, reflectionId?, initialBody, date, onSave, onCancel)`: 현재 기록에만 연결. 입력 자동 높이 확장; 별도의 제목·감정 태그 없음. 중복 저장 방지/네트워크 오류/취소 확인/키보드 시 안전한 가시성은 실제 앱 검증 필요.
- `ReflectionItem(reflection, onEdit, onDelete)`: 날짜, 원문과 동일한 본문 타이포, 44px 더보기. 수정 시 최초 날짜 유지.
- `JarArtwork(noteCount, phase)`: V7 확정 재질/실루엣 재사용. 0/1/3/5 시각 개수. 애니메이션 상태와 원본 데이터 분리.
- `DrawMotion`은 기존 V7의 곡면과 타임라인 재사용. 재진입은 닫힌 초기 상태, 감소 모션 지원.
- 제품 화면에서는 개발자 설정, 재생/배속, 강제 시나리오, 키보드 모의 영역을 노출하지 않는다.

## 4. 데이터/백엔드 설계 제안 (실제 스키마 확인 후 통합)
`diary_entries` 1:N `diary_reflections`.
- 신규 필드 후보: `id` (UUID PK), `entry_id` (원본 FK, ON DELETE CASCADE), `body` (text, 비공백), `reflection_date` (date), `created_at`, `updated_at` (timestamptz).
- 사용자 소유권은 원본 일기와 연결해 검증. RLS에서 읽기/생성/수정/삭제 모두 소유 원본만 허용. 다른 사용자의 ID, 원본 변경, 날짜 위조를 막는다. 원본 삭제 시 덧붙인 마음도 삭제됨을 사전 안내. 원본 수정 시 마음은 유지. 실제 DB의 기존 테이블/인증/삭제 정책과 대조 후 마이그레이션 작성.
- 작성일은 제안상 실제 KST 날짜, 수정으로 변경하지 않음. 사용자 하루 경계 설정을 적용할지 별도 제품 검토 필요. 서버 생성 시각과 표시 날짜 분리. 같은 날 여러 개 허용, 생성 시각 및 ID 안정 정렬.
- 월간 작품, 기록일수, 최초 해제 10개, 병 구도, 무작위 추첨, 기록 목록 단위는 **원본 일기만** 집계. 마음은 원본에 포함해 읽되 별도 집계하지 않는다.
- 저장 요청 중 중복 방지, 재시도 idempotency, 동시 수정/삭제 충돌, 오프라인 정책, 계정 전체 삭제, 인증/권한 테스트는 서버 작업에 포함. 일기/마음 본문은 분석 이벤트·로그에 기록하지 않는다.

## 5. 프로토타입 검증 결과
- V7 HTML 원본을 바탕으로 독립 HTML V8 수정. 기존 앱 코드/DB/GitHub 미변경.
- Chromium Playwright: 0/1/3/5 구간, 9→10 최초 해제, 해제 후 0/1/3개 상태, 일반 추출, 감상 후 닫기, 마음 생성/수정/삭제, 저장 실패 재시도, 미저장 닫기 계속/폐기, 같은 원본의 전체 목록 및 달력 공유, 달력 날짜 복귀, 320px 긴 기록 가로 넘침 없음, 감소 모션 검증 통과. 실행 중 JS 예외 없음.
- 환경 정책상 file://와 localhost 직접 탐색 차단. HTML을 Chromium에 set_content로 주입하여 검증했고 외부 폰트 요청은 차단. 세션 저장 코드는 존재하나 브라우저 원점이 없는 이 검증에서 실제 새로고침 지속성은 미검증. 키보드 280px 모의는 실제 iOS/Android 키보드가 아님. 실제 웹폰트·WebView·모바일 GPU·React 통합·DB 접근 제어는 미검증.
