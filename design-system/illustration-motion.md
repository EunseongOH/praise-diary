# 테마별 타이포그래픽 아트 디렉션 · v0.4

> 단계: **눈꽃 아트 프로토타입**. 사용자가 원하는 시각적 완성도는 아직 미확정. 디자인 검수 없이는 '완성'이라고 표시하지 않는다.
>
> 2026-11-21 논의: 상징물의 줄기·곡선·질감에 맞춰 글자를 놓고, 같은 형태의 물성에 맞춰 미세 회전·진동을 설계한다.

## 1. 모든 월에 공통으로 적용할 원칙 (확정)

1. **아래에서 위로:** 새로운 `entry_date`에 처음 저장한 일기가 그달의 실루엣을 아래에서 위로 확장한다. 보여주지 않은 상단 윤곽선은 미리 나타나지 않는다.
2. **하루 여러 편:** 날짜당 일수는 한 번만 증가한다. 같은 날짜의 추가 일기는 현재 드러난 영역 안에서 글자 구성이 더 풍성해져야 한다. 높이를 올려서는 안 된다.
3. **상징물에 종속된 모션:** 무작위 위치·회전·가속 대신 경로 탄젠트(줄기/곡선 방향), 관절·접합점(회전축), 재료 감각(눈꽃/양털/태양)을 정의한다.
4. **정지된 작품의 완성도:** 모션을 끄거나 썸네일로 보아도 실루엣·여백·밀도가 좋아야 한다. 화려한 효과로 형태적 결함을 가리지 않는다.
5. **원문 존중:** AI가 만든 칭찬 문구를 그래픽에 끼워 넣지 않는다. 사용자가 쓴 글자만 내부에 활용한다. 글자 복제/추출은 그래픽 질감 용도이며 실제 일기 원문을 그대로 재조합·외부 공유하지 않는다.
6. **불필요한 시각 효과 금지:** 다색 글로우, 임의 점멸, 무관한 작은 별·스파클, 3D 회전 남발 금지. 기존 다크 색상은 임시 시안이며 그래픽 색을 고정하지 않는다.
7. **접근성:** 기록의 내용·날짜·저장 성공 등 핵심 정보는 별도 텍스트로 표시. 시각적 움직임 없이도 확인 가능. OS 및 앱의 reduced motion 설정에 따라 반복 모션 중지.

## 2. 눈꽃 — 형태와 움직임

### 배치

- **여섯 갈래 큰 줄기**는 중심에서 60° 간격으로 방사. 각 줄기의 글자는 줄기의 접선 방향으로 정렬하되 미세한 시각적 오차만 허용.
- 각 줄기마다 **세 쌍의 작은 가지**를 배치하고 가지의 방향으로 글자의 기준각을 재설정. 6×(1+6)=42개 구조 그룹이 모델링됨.
- 글자 크기·투명도·간격에는 작은 차이만 부여. 중심부에서는 지나치게 포개지지 않도록 글자 위치를 제어한다.
- 화면 전체는 하나의 캔버스. 눈꽃만 다른 배경 카드 안에 담지 않는다.

### 움직임

- 줄기: 시작점을 축으로 약 **±0.3~0.55°** 정도의 매우 작은 회전, 약 8~10초 왕복.
- 가지: 자기 줄기에서 갈라지는 **접합점을 축**으로 약 **±0.85~1.31°**, 약 5.7~7.4초 왕복.
- 시간 위상을 서로 어긋나게 설정해 **동시에 흔들리지 않도록** 함.
- 회전축이 가지의 끝이나 SVG 전체 중앙이 아니라 **해당 가지의 뿌리**에 있어야 함.
- 개별 글자를 독립적으로 매 프레임 랜덤 회전시키지 않음. 글자는 자기 가지에 붙어 움직임.

### 현재 코드

- `src/graphics/glyphLayout.ts`: 방사형 줄기와 가지의 **독립 로컬 좌표계/탄젠트 방향/회전 크기/위상**을 결정적으로 생성.
- `src/graphics/GraphicArtwork.tsx`: 글자를 각 가지 좌표계에 배치하고 `<animateTransform>`으로 가지의 축을 기준으로 미세 회전. 이미지와 도감 축소판에서는 반복 모션 생략.
- `src/graphics/progress.ts`: `writtenDays`의 고유 날짜 수로 세로 리빌 클립 계산. 기입일이 증가할 때에만 새 영역을 애니메이션으로 보여줌.
- `snowflake-art-direction-preview.html`: 날짜 수, 같은 날 일기 추가, 밀도, 움직임 정지 비교가 가능한 정적 테스트 페이지.

### 지금 단계의 남은 결함 — 출시 전 해결 필수

- 글자 크기와 가지 수는 아직 벡터 디자이너가 다듬은 최종 원화가 아니며, 일부 해상도에서 가지 연결부의 획이 뭉칠 수 있음.
- 현재 그리기 함수의 **글자 선택은 `letterSource` 전체를 기반으로 리샘플링**한다. 일기를 추가하면 일부 기존 슬롯의 글자가 바뀔 수 있음. 실제 배포 전 `entry_id`별 고정 글자/슬롯 할당을 도입해야 개별 일기 삭제·복원과 입자 연속성이 보장됨.
- 슬롯 수가 가득 차는 후반에는 추가 일기의 새 글자를 계속 담기 위한 **2차 밀도 레이어**와 겹침 제한이 필요함.
- 그래픽을 확대했을 때 하나의 큰 단어·문장을 읽어낼 수 없도록 하는 프라이버시 정책 검토 필요.
- 실제 기기에서 CPU/메모리/배터리/플랫폼 접근성을 검증해야 함.

## 3. 붉은 양과 해 — 구현 전 모션 설계

이 시점에는 **원화 및 전용 글자 배치/모션 엔진이 미완성**이다. 눈꽃의 방사형 모션을 복사하지 않는다.

| 요소 | 글자 흐름 | 권장 모션 컨셉 | 주의 |
|---|---|---|---|
| 몸통의 양털 | 둥근 곡선·나선 결에 따라 글자 배치 | 넓은 면이 아주 천천히 호흡하는 듯한 미세 이동 | 통째로 빙글빙글 돌지 않기 |
| 머리·귀 | 윤곽의 접선 및 연결점을 따라 배치 | 귀 끝 또는 머리 주변의 국소 움직임 | 표정·실루엣 깨지지 않기 |
| 다리 | 아래로 내려가는 글자의 수직 흐름 | 거의 고정 | 발이 떠 보이지 않기 |
| 해 | 중심을 기준으로 방사형 글자 밀도 | 미세한 호흡·밝기 변화(검증 후) | 과한 글로우·무의미한 회전 금지 |

## 4. 아트 QA — 디자인 검토 기준

- [ ] 정지 상태 320px 폭에서도 무엇을 상징하는지 알아볼 수 있다.
- [ ] 첫날의 낮은 부분은 의도적인 시작 형태이고, 텅 빈 오류 화면처럼 보이지 않는다.
- [ ] 절반 진행 시 중간 높이까지만 보이며, 위쪽의 완성 윤곽이 보이지 않는다.
- [ ] 모두 채워진 후에도 글자 겹침과 빈 구멍이 무작위처럼 보이지 않는다.
- [ ] 가지별로 배치 방향과 회전축이 다르고, 서로 같은 위상으로 떨지 않는다.
- [ ] 작은 썸네일에서는 모션 없이도 형태가 살아 있다.
- [ ] 하루에 여러 번 쓰면 높이는 유지하고 글자 질감은 달라진다.
- [ ] 일기 수정/삭제 시 관련 글자만 안정적으로 바뀌거나 제거된다. **현재 미구현**.
- [ ] 저사양 Android와 iPhone에서 60fps 목표/30fps 허용/정적 폴백을 검토한다.
- [ ] `prefers-reduced-motion` 및 앱의 움직임 줄이기에서 반복 모션이 꺼진다.
- [ ] 색상 대비 및 글자 가독성, 글자 확대, 긴 일기, 접근성 라벨을 실기기에서 검사한다.

## 5. 이번 단계에서 확정/미확정

**확정:** 상징물별 글자 배치 방향과 회전 원칙, 아래에서 위 성장, 동일 날짜 추가는 내부만 풍성하게, 무경계 캔버스, 미적 QA 필요.

**임시 구현:** 눈꽃 글자 파티클의 수, 배치 좌표, 42개 구조 그룹, 0.3~1.3° 회전, 5.7~10초 모션. 이는 테스트용 수치이며 최종 미감 승인 전 조정 가능.

**미확정:** 최종 서체와 눈꽃 시안, 색상, 원문-입자 매핑, 양과 해의 벡터 경로/애니메이션.
