# 칭찬일기 디자인 원칙

## 1. 콘텐츠가 주인공
- 월간 텍스트 그래픽은 그달의 칭찬 기록을 담는 작품이다. 일수·상태·성취 배지보다 먼저 본다.
- 화면은 '대시보드'가 아니라 조용한 일기장처럼 보여야 한다.
- 강한 채움색은 화면당 주요 행동에 집중. 빈 공간을 카드로 무조건 메우지 않는다.

## 2. Anti-slop 체크리스트
- [ ] 설명 없이 붙은 아이콘은 제거한다. 기본 내비게이션은 텍스트만으로도 이해 가능하다.
- [ ] 모든 섹션을 둥근 카드/그림자로 구분하지 않는다.
- [ ] 그라데이션·글로우·인위적인 볼륨·이모지 타일을 장식 목적으로 사용하지 않는다.
- [ ] 실루엣·글자 모션 외의 무의미한 애니메이션은 없앤다.
- [ ] 질문 유형, 데이터 상태, 내부 진행 코드, '9/15' 대형 게이지를 사용자에게 노출하지 않는다.
- [ ] 과장된 칭찬이나 AI가 지어낸 감성 문구 대신 사용자가 실제 쓴 문장을 보여준다.
- [ ] 제목/설명 중복, '여기를 클릭', 잦은 느낌표 등은 점검한다.

## 3. 재사용 인터랙션
- 상단바는 뒤로가기·현재 화면명·상황에 필요한 보조 액션만 제공.
- 하단바는 주요 영역 3개: 홈·꺼내보기·도감. 설정은 홈 상단에서 열기.
- 스위치는 즉시 적용되는 설정에만, 선택형 버튼은 오늘/어제·시간 경계 등 단일 선택에만.
- 삭제 다이얼로그는 관련 기록의 영향/불가역성을 구체적으로 설명. 전체 삭제는 여러 단계 확인.
- 토스트는 저장·변경 결과 피드백에만. 날짜 귀속은 작성 상단에서 계속 보여준다.

## 4. 접근성·성능
- 탭·버튼 최소 터치 높이 44px; 초점 명확히; `aria`와 의미론적 요소 우선.
- 색만으로 상태 표시하지 않으며, 대비 검증. 사용자 글은 16px 이상.
- `prefers-reduced-motion`과 사용자 '움직임 줄이기' 설정 모두 적용.
- 그래픽 모션이 실패해도 정적인 SVG 상태와 일기 기능이 가능해야 한다.
- 모바일 키보드, 동적 viewport/safe-area, 긴 한국어 본문을 우선한다.

## 5. 색상 시스템 후보(2026-11-21)
- 라이트 바탕 `#FFFFFF`, 제안 팔레트 `#B8D68A`, `#61AE72`, `#FAD89E`, `#A6C5D3`. 확정된 브랜드 테마가 아닌 비교 후보.
- 텍스트는 별도 어두운 포레스트 계열 `#273C2F`. 그래픽 아트 영역은 필요시 `#162A28` 어두운 무대 활용.
- 상세 대비 수치와 적합성 검사는 [color-system.md](color-system.md) 및 `npm run check:contrast` 참고.
- 색으로만 작성일·완성 여부를 표현하지 않도록 숫자와 ARIA 안내를 병기한다.
