# 칭찬일기 — UI 디자인 품질 기준 (Anti-slop Checklist)

- 버전 v1.4 / 2026-11-21
- **[확정]** 먼저 IA/화면/기능을 결정하고 Seed, Shopify Polaris, Toss TDS, Material Design을 비교하여 타이포 위계·색상·컴포넌트를 설계.
- **[확정]** AI가 만든 것처럼 보이는 억지스러운 아이콘·장식·반복 카드 패턴을 피하고, 사용자에게 불필요한 정보(질문 유형·내부 코드·상태 이름) 비노출.
- **[참고]** Damir Sokolovsky의 [unslop](https://github.com/heydamir/unslop) 공개 프로젝트의 접근(문제점 감사 → 제품 특성 기반 방향 설정 → spacing/color/icon/copy/type/layout/details/visuals/motion 순 정돈)을 참고한다. 이 문서는 외부 스킬을 설치/실행했다는 뜻이 아니며, 실제 구현 전 별도 점검에 사용할 체크리스트이다.

## A. 원칙

1. **의미 없는 아이콘 금지**: 텍스트로 충분한 항목에 장식용 아이콘을 붙이지 않기. 실제 동작을 보조하는 경우만 사용.
2. **한 화면에 명확한 한 가지 주 행동**: 보조 동작은 텍스트 링크·낮은 위계. 위험한 삭제/해제는 맨 아래 구분.
3. **그래픽에만 시각적 특별함 집중**: 눈꽃/붉은 양·해 텍스트 파티클이 제품 서명. 설정/기록 목록까지 발광·그라데이션 적용 금지.
4. **묶음 기준으로 레이아웃**: 모든 콘텐츠에 별도 카드 남발하지 않고, 목록·행·구분선을 우선 활용.
5. **문구가 UI를 설명하지 않게**: 자연스러운 버튼 레이블과 상태 텍스트만으로 이해. ‘관계’, ‘용기’ 등 질문 유형 비노출.
6. **타이포 위계**: 제목→행 제목→보조 설명→메타; 한 화면에서 너무 많은 굵기/크기 사용 지양. 이미지/그래픽 우선 장면만 예외.
7. **균일한 정렬과 간격**: 임의 padding·radius·아이콘 크기 사용 지양. TDS 컴포넌트 지원 범위·미니앱 네비게이션 준수.
8. **접근성**: 글자 크기·명도 대비·터치 타깃·스크린리더·움직임 줄이기·오류 복구 우선 검증.
9. **기능이 있는 모션만**: 작성→그래픽 성장, 추가→글자 이동, 삭제→축소 등 원인·결과를 나타내는 모션. 설정 화면의 장식성 모션은 생략.
10. **실기기 검증**: 모니터 목업보다 토스 WebView의 성능, 키보드, 안전 영역, 네비게이션 및 터치 충돌 확인.

## B. 실무 디자인 리뷰 절차 [제안]

- 화면별 기능 명세와 상태 목록을 먼저 동결한다.
- 제품의 시각적 캐릭터/세계관과 대표 장면 1~2개를 정한다.
- Seed·TDS·Polaris·Material 중 재사용할 컴포넌트/패턴을 선정하고, 조합이 충돌하지 않도록 단일 토큰 계층을 설계한다.
- 화면을 실제 크기로 렌더해 아래 체크리스트를 검토한다.
- 문제를 발견한 요소만 수정하며, 이미 좋은 부분은 억지로 재디자인하지 않는다.

## C. 체크리스트

- [ ] 화면 내 아이콘마다 기능상 이유가 있는가?
- [ ] 카드/버튼/배경이 필요 이상으로 반복되지 않는가?
- [ ] 서비스 그래픽을 제외한 불필요한 발광·그라데이션이 없는가?
- [ ] 가장 중요한 CTA가 명확한가?
- [ ] 모든 문구가 이용자에게 필요한 정보인가?
- [ ] 제목·본문·부가 정보의 위계가 일관적인가?
- [ ] 보조 링크, 삭제 등의 위험 액션이 적절한 위계를 갖는가?
- [ ] 임시·로딩·오류·빈 상태와 큰 글씨에서도 구성이 안정적인가?
- [ ] 모바일 안전 영역·키보드·뒤로가기가 정상 동작하는가?
- [ ] 화면이 스스로 자연스럽고 명확한지, AI 템플릿처럼 보이지 않는지 전체 리듬을 다시 검토했는가?
