## 0. 목적과 우선순위

[확정] 사용자는 개별 일기를 그래픽에서 완전히 읽는 것보다 **앱에 들어왔을 때 눈꽃의 조형이 아름답게 보이는 것**을 우선한다. 전체 원문은 별도의 일기 목록·상세 화면에서 접근 가능하다. 그래도 글자가 사용자의 실제 기록에서 왔고, 확대하면 대표 나선의 **원문 일부가 연속해서 읽히는 성질**은 남긴다.

[확정] 짧은 일기를 쓴 사용자도 동일한 작성일 수에 도달하면 충분한 완성감의 눈꽃을 얻도록, 원문의 짧은 구절을 **반복 나선(echo)**으로 여러 번 배치하는 것을 허용한다. 과거 문서 19·20·22의 '원문 반복 금지'는 **대표/독해 나선의 원문 왜곡 및 여섯 줄기에 한 문장을 임의로 동일 배치하는 것을 막기 위한 규칙**으로 한정한다. 이 새로운 승인 아래에서 **출처가 명시된 echo 반복은 허용**한다. 새 문장 생성/AI 요약/의역은 여전히 금지한다.

[확정] 대표 나선은 큰 줄기 또는 읽기 좋은 핵심 축 위주, echo는 작은 가지·외곽·밀도가 부족한 부분 위주. 대표 나선의 위치는 안정적으로 보존하되 echo는 새 일기 등장 시 배치를 바꿀 수 있다.

[확정] 한 일기의 아직 공개할 수 없는 글자는 **미래 성장 영역에 좌표를 미리 예약**할 수 있고, 고유 작성일 수가 늘면 그 위치에서 새로 드러난다. 실제로 열리지 않은 높이에서는 글자·유령 윤곽 모두 숨긴다.

[연구] 이번 2C는 **레이아웃/원문 배정 변경만** 검증하고, 이후 B(회전+상관 부유) / C0(B+밝아짐) / C1(B+어두워졌다 복귀) 모션을 동일한 개선 geometry에 다시 적용한다. 미감과 성능이 통과하지 않으면 실서비스 전환 금지.

## 1. 이전 Gate 2B의 알려진 실패 사례 — 사용자에게 전달된 Claude Code 보고값

- 기본 길이: 15일 총 202자, 표시 185자이나 1×와 160px에서 눈꽃 실루엣 약함.
- 긴 글: 15일 총 617자 중 표시 613자, 여섯 갈래 눈꽃 인지 가능하다는 구현자 보고.
- 아주 짧은 글: 15일 약 44자에서 실루엣 더 빈약.
- 첫날: 열린 높이 1/15에서 전체 배치 2자, 0° 화면 가시 1자. 처음 못 놓은 글자는 이후에도 들어오지 않음.
- 일부 날짜 동일일 추가 +2가 가시 변화 0. 긴 글 15일 +2도 가시 증가가 매우 작음.
- 중심 반경 근처 과밀, 가지 뿌리 뭉침, ±30° 축의 글자 독해성 부족.
- 긴 글 15일 +2, DPR2에서 CPU1× B 26.4fps/C0 27.2fps로 30fps 미달. C1의 단일 58.2fps는 반복 측정값이 크게 흔들린 이상치. 실기기 성능 미검증.

이 수치는 직접 구현 검증값이 아니라 전달 보고다. 새 테스트는 같은 fixture와 실제 그린 글자 수를 보존해 비교한다.

## 2. 아키텍처: 원문 / 대표 나선 / echo / 슬롯 / 가시성의 분리

**DiaryEntry**: monthId, entryId, entryDate, originalBody, stable createdAt or deterministic orderKey, revision. 같은 날짜 편수와 고유 작성일 수를 혼동하지 않는다.

**SourcePhrase**: entryId, 원문 grapheme offset의 시작·끝, **원문 그대로의 연속 구절**. 구두점·공백·한글/영문/이모지 원본 보존. '좋은 문장'을 AI로 생성·순위화하지 않는다.

**StrandAssignment**: strandId, role(anchor 또는 echo), entryId, sourceStart/sourceEnd, copyIndex(대표는 0), axisId, zoneId, trackId, radius/phase, stable artVersion, anchorSlotId, revealStage. source span과 copyIndex를 통해 같은 원문이 왜 반복되는지 역추적 가능.

**GlyphInstance**: strandId + sourceOffset + localIndex + copyIndex; 같은 원본 글자라 해도 echo는 다른 instance. 원문 글자를 실제로 복사해서 새로운 일기 기록으로 저장하지 않는다.

**PlacementLedger**: 어떤 기록이 어떤 월/축/구간에 자리를 예약했는지 보존하는 실험용 결정적 기록. 초기 연구는 가상 fixture만 사용하며 실제 고객의 영속 데이터 모델·마이그레이션을 이 Gate에서 확정하지 않는다. 새 프레임/재시작마다 전역 재배치하거나 Math.random을 사용하지 않는다.

**Visibility**: 작성일 고유 개수 U가 확장한 전역 월간 높이 및 글자 전체의 투영 경계에 의해 결정. echo/anchor의 role이 성장 높이를 늘리지 않는다.

**렌더링**: 좌표와 원문 선택은 데이터 변경 시 계산; 회전·부유·shimmer는 단일 animation clock으로 계산. 매 프레임 원문 구절 추출/ledger 재배정/React 전체 glyph 재렌더링 금지.

## 3. 자연스러운 구절 추출 v1 [연구안]

한국어에서 '의미상 가장 좋은 표현'을 자동으로 추론하는 것은 이번 작업 범위가 아니다. 우선 **결정적이고 추적 가능한 어절·구두점 기반 분할**을 한다.

1. 원문을 Unicode grapheme cluster 기준으로 인덱싱(Intl.Segmenter 지원 시 사용, 미지원 시 안전한 대체). sourceStart/sourceEnd는 원문의 해당 grapheme 범위를 가리킴.
2. 문장부호(마침표·느낌표·물음표), 줄바꿈, 쉼표에서 경계 후보를 얻되 실제 원문 기호를 새로 만들거나 삭제하지 않는다.
3. 공백을 기준으로 어절 단위를 구하고, 인접 어절을 **원문 순서 그대로 결합**해 자연스러운 짧은 연속 구절을 얻는다. 시작 탐색 길이 **6~12 grapheme**는 목표 범위이지 강제 자르기 규칙이 아님.
4. 2~5자 초단문은 **그 자체가 완전한 원문**이므로 그대로 echo로 사용할 수 있다. 길이를 맞추기 위해 가짜 글자·마침표·공백을 붙이지 않는다.
5. 한 어절이 길거나 영어/숫자/이모지가 혼용되어도 grapheme·단어 중간 절단을 먼저 하지 않는다. 너무 긴 경우 필요한 만큼 원문 연속 범위로 표시하고 truncation을 기록.
6. 지나치게 짧은 조각은 가능하면 이웃 어절과 결합하되 임의의 '응원 표현'으로 바꾸거나 다른 문장의 글자를 합성하지 않는다.
7. 추출 결과의 각 출력 glyph는 원문 위치로 되돌아갈 수 있어야 한다. 반복본은 다른 문장처럼 읽히도록 서로 이어 붙이지 않는다.

테스트 예: 원문이 '오늘 피곤했지만 끝까지 해냈다. 그래서 내 자신이 조금 대견했다.'이면 원문에서 '오늘 피곤했지만', '끝까지 해냈다.', '그래서 내 자신이', '조금 대견했다.' 등의 **연속 구절 후보**를 추출. 후보의 실제 채택과 기호 포함 여부는 원문 인덱스·어절 경계에 따라 결정. 문장의 의미를 임의 보정하지 않는다.

## 4. 대표 나선(anchor): 원문 흔적, 안정 슬롯

- **일기당 기본 1개**를 우선. 한 축의 수용 범위가 모자라거나 긴 기록이면 **인접하고 연결된 2개 이상의 대표 구간**을 연구 후보로 허용하되, 그 이유·수·원문 범위를 보고. 이 수치는 제품용 고정 1~2개 제한이 아니다.
- 우선 큰 줄기 또는 글자 각도가 비교적 읽기 좋은 축에 배치. 중심부·가지 뿌리 과밀 지역은 피한다.
- 한 anchor에서 보이는 문자는 원문에서 **연속된 범위**이고 순서가 보존된다. 나선 회전 중 뒷면에서 잠깐 가려지는 것은 정상.
- **생성 시점 ledger 예약**: 일부 글자는 현재 열린 성장 구간에, 나머지는 아직 공개되지 않은 상단의 허용 슬롯에 기록할 수 있다. 최초 저장한 날 **보이는 완전한 글자**가 적어도 일부 있도록 배치 우선순위를 둔다.
- 새 일기 추가로 기존 anchor의 hostAxis, anchorSlotId, 월간 좌표·위상이 변하지 않도록 한다. 기존 글자 위치의 이동 없이 아직 예약된 문자들이 나중에 노출된다.
- 실제 날짜가 과거(예: '어제')인 기록이 뒤늦게 추가되어도 전역 U는 **서로 다른 entryDate 수**이고, 과거 기록의 좌표를 일괄 재정렬하지 않는다. 연구 ledger는 해당 날짜가 처음 등장한 순서를 기록해 좌표 안정성을 확보한다. 이 '배정 순서'는 월간 완료일 계산의 새로운 정책이 아니며 사용자 화면에 표시하지 않는다.
- 같은 기록 본문 수정: 원문의 변경된 길이에 맞춰 그 기록의 anchor 내용만 갱신. 늘어난 부분은 인접·향후 슬롯에 배정하고, 불가능하면 표시 가능한 연속 구절만 유지. 다른 기록의 anchor를 재배치하지 않는다.
- 해당 기록 삭제: 연결된 anchor와 echo 일괄 제거. 해당 작성일의 마지막 기록 삭제로 U가 줄면 성장 경계가 낮아지는 건 정상이며, 다른 기록의 좌표가 이동한 것은 아님.

## 5. 반복 나선(echo): 조형 부족분만 보강

- **짧은 원문 일부 구절 반복 허용**은 이번 Gate의 가장 중요한 새 규칙. 반복 횟수는 '일기당 n회'로 고정하지 않고 현재 표시 영역과 눈꽃 실루엣의 밀도 부족에 따라 정한다.
- **우선 채울 구역**: 가지 끝·작은 가지 중간의 빈 구간 → 외곽 실루엣 → 큰 줄기의 성긴 연결부. 중앙 반경 및 가지 뿌리는 충돌 패널티를 높여 과밀 방지.
- **대칭성**: 큰 줄기 여섯 방향의 균형을 우선, 각 구역 글자 표면의 작은 차이와 비동기 위상은 허용. 같은 한 구절을 여섯 곳에 일괄 도장 찍듯 동일한 위상으로 배치하지 않는다.
- **목표 밀도 함수 [연구]**: currentlyOpenRegion의 실루엣 축 커버리지, 가지 연결성, 중심 충돌, 각도별 앞면 가시 glyph 수, 160px 타일의 선 굵기를 측정. axis/twig/zone별 부족 정도에 의해 다음 echo 슬롯 선택. 고정 생성 수보다 **부족한 부위**와 **충돌 위험**을 평가한다.
- **결정적 선택**: 가장 부족한 구역부터 후보 슬롯을 정렬하고 원문 구절 후보를 안정 seed로 분산. 인접한 echo에서 동일 구절이 반복돼 단어가 덩어리로 보이지 않도록 간격·위상 패널티 적용. 장식 text도 실제 원문 범위·entryId·copyIndex 추적.
- **anchor 우선권**: 새 일기가 저장되고 현재 열린 영역에 anchor 자리가 필요하면 echo 일부를 지우거나 다른 슬롯으로 옮겨 양보한다. anchor의 좌표는 변경하지 않는다.
- **echo 이동 제한**: 가능한 한 가장 작은 변동을 우선한다. 모션 중 갑자기 다른 위치로 순간 이동해 보이지 않도록 데이터 변경 시 짧은 상태 전환을 추후 비교할 수 있으나, 본 Gate는 정적 스냅샷 변화도 먼저 검수한다.
- **포화 처리**: CPU·메모리·충돌 한계를 넘어 무한히 반복해 160px의 글자 뭉침을 만드는 건 허용하지 않는다. 안전 상한은 실험값으로만 명시. 그 상한으로도 목표 실루엣을 얻지 못하면 **시각 실패**로 보고하고 실제 일기 데이터/글자를 가짜로 보완하지 않는다.
- **극단 2~3자 입력**도 원문 일부로 echo 허용. 15일이 지나도 무작정 같은 위치에 똑같은 글자만 겹치지 않도록 분산하되 실제 원문에서만 글자를 가져온다.

## 6. 미래 예약·아래에서 위로 성장·첫날·동일 날짜

### 6.1 날짜 계산
- U = 해당 월에서 실제 저장된 entryDate의 DISTINCT 개수. 연구용 정규 목표 T=15에 대해 progress = min(U/T, 1).
- 2026년 12월 특별 목표는 미정. 이번 개발 페이지의 15일 수치를 실제 12월 완료 정책에 적용하지 않는다.
- 과거 기록 변경, '어제' 추가, 동일일 추가 등에도 실제 작성일 귀속은 기존 날짜 정책을 따른다.

### 6.2 미래 슬롯
- 어떤 일기에 대해 여러 단계의 glyph 슬롯을 예약할 수 있으나 **현재 U로 공개된 구간에서만 그린다**.
- 미래 위치의 자리 표시자, ghost 윤곽, 더 높은 가지의 미리보기, 축 가이드가 기본 작품 캡처에 노출되면 실패.
- **표시 대상인지 판정할 때 회전·부유 후 투영된 글자의 전체 바운드**를 검사해 완전한 glyph만 노출. 성장 clip으로 반만 자르지 않는다.
- 예약한 슬롯과 구절의 source offset이 미래 공개 때도 변하지 않아야 한다. 단 기존 echo는 anchor 충돌 시 재배치 가능한 가변 슬롯.

### 6.3 첫날의 '눈꽃 씨앗'
- 첫날 성장 높이를 몰래 2/15 이상으로 확대하지 않는다.
- **정확히 1/15 열린 하단 영역 안**에서 anchor와 echo의 국소적인 방사·나선 밀도를 높여, 정면에 한 글자만 찍힌 빈 화면보다 잘 보이는 작은 조형을 목표로 한다.
- 첫날 모든 글자를 보여주지 않아도 되며, 나머지 anchor 원문은 미래 슬롯에서 점차 등장해야 한다.
- 한두 글자 원문을 반복해도 영역에 물리적 공간이 모자라면 한계를 측정하고 실패를 기록한다. 사용자 몰래 위쪽 영역을 공개하는 해결 금지.

### 6.4 동일 날짜 추가
- 같은 날짜에 두세 편 기록을 저장해도 progress/revealTop은 변하지 않는다.
- 초반 1~3일, 중간 8일, 포화 15일에서 새 기록의 최소 일부가 **정지 기준 시간·각도** 또는 일정 관찰 구간 동안 드러나는지 확인한다. 먼저 echo 자리를 비워 새 entry의 anchor를 우선한다.
- 무제한 같은 날 기록 수에 대해 가시 글자 무조건 증가를 **수학적으로 보장한다고 주장하지 않는다**. 포화 시 남은 슬롯, 신규 anchor 가시 여부, 제거/이동된 echo 수를 출력해 UI 보완이 필요한지 나중에 결정한다.

## 7. 비교 설계 — 모션보다 조형 먼저

**기준 그룹 G0:** 기존 Gate 2B 눈꽃, 현재 짧은 문장 실루엣과 1일 문제를 그대로 비교 대상으로 캡처(기존 코드는 변경하지 않음).
**연구 그룹 G1:** anchor만 안정 예약, echo 없음. 1일/15일 글자 배치 안정성 및 미래 공개를 검증하는 기능적 대조군.
**연구 그룹 G2:** anchor + density-adaptive echo. 이번 실험의 디자인 후보.

세 그룹의 원문·색·서체·고정 카메라·성장 경계는 같으며, G2만 echo가 늘어날 수 있으므로 **총 glyph 수가 다르다는 사실을 명시**한다. G1/G2는 원문이 중복되지 않는 anchor와 출처 있는 echo로 구분한다.

**시각 검수 우선순위:** ① 15일 기본/ultra-short 1× 눈꽃 형태 ② 160px 도감 인지성 ③ 1/3/5/8일 단계의 성장감 ④ 1일 +2의 변화 ⑤ 중심/가지 겹침 ⑥ 2×/3.2× anchor 독해.

정지형 G2 레이아웃을 확인한 다음에만 **같은 G2 기하와 글자 수**에 B/C0/C1의 로컬 나선 회전·상관 부유·문자 자체 shimmer를 적용한다. 별 입자, 복제 그림자, 파티클 추가 금지. 기존 C0 +10%, C1 −28%는 단순 비교값이며 **최종 강도는 미확정**.

## 9. 자동 테스트·검수 조건

**데이터 순수성**
- 모든 anchor/echo glyph의 entryId/sourceOffset/copyIndex가 fixture 원문에 실제 존재. 가짜 문장 0.
- echo는 원문 짧은 연속 부분 구절이며 다른 일기 단어와 결합한 문장 0.
- phrase 추출 결정적, grapheme·어절 내 절단/임의 첨가 0. 초단문·한글/영문/이모지·공백 처리.
- 중복 출처는 반드시 role=echo로 추적, 일기 목록/작성일 통계에는 추가 기록으로 계산되지 않음.

**배치 안정성**
- 입력 순서를 바꾸어도 ledger가 같은 상태로 재현, 같은 프레임 결과가 결정적.
- 새 일기/동일일 추가 전후 기존 anchor의 axis/slot/원문 범위 유지. echo만 필요한 범위에서 이동/퇴출.
- 본문 수정·개별 삭제·작성일 마지막 일기 삭제 후 다른 anchor 불필요한 이동 0. 성장 높이 감소는 별개.
- 0일 미표시, 1/3/5/8/15일의 글로벌 높이 정확, 같은 날 추가 시 높이 변화 0.
- 미래 예약 glyph가 해당 높이 공개 전 노출되지 않고, 나중에 실제로 노출됨. 모든 각도·시간 샘플에서 반쪽 glyph 0.

**조형과 모션**
- 1× 및 160px 타일에서 기본/초단문 눈꽃으로 **보이는지 사용자가 직접 검수**; 자동 metric PASS만으로 디자인 승인 금지.
- 6개 큰 축/36개 가지의 완성 단계 활성화 수, 실제 그린 글자 수, 각 축 coverage, 중심 겹침 밀도 보고.
- B/C0/C1은 같은 geometry/position/occlusion/seed/time에 shimmer만 다름. reduced-motion에서 정지.
- 글자 반복이 새 장식/가짜 기록으로 보이지 않고, anchor는 가까이서 일부 실제 연속 구절을 읽을 수 있어야 함.

**성능**
- Gate 2B 대비 echo glyph가 증가함을 숨기지 않는다. 같은 base/long/ultrashort와 단일 B/C0/C1에서 375×812, DPR1·2, CPU1×·4×, Chromium headless 10초×3회 median/p95, 실제 drawImage/glyph 수, 캐시·메모리·FPS 출력.
- 실기기 GPU/WebView 성능은 별도 검증 전까지 미검증. CPU4× GPU 없는 환경은 노이즈 큰 참고값일 뿐 제품 판단 근거 아님.
- 실험 통과를 위한 별도 목표: 375px DPR2 단일 작품에서 CPU1× **30fps 이상 지향**, 60fps 목표. 미달 시 명확히 FAIL. 증가된 echo를 몰래 제거해 숫자 맞추지 않음.
- Canvas atlas/bitmap 캐시 공유, 축/구간 단위 정적 캐시, 도감 타일은 정지 이미지, 화면 숨김/ reduced-motion에서는 반복 렌더 중단 후보. WebGL2 전면 도입은 측정/실기기 확인 없이 확정하지 않는다.

## 10. 구현 단계와 중단 기준

- **2C-0**: 로컬 기존 G0 재현 캡처, source/ledger 모델 및 phrase extraction, unit test.
- **2C-1**: 대표 나선 예약/안정 슬롯, 미래 공개, 0/1/3/5/8/15일 정적 비교 G1.
- **2C-2**: 밀도 적응 echo G2, 짧은 글/초단문/동일일/수정삭제, 형태·출처 안정성 테스트. 실제 15일 1×와 160px에서 여전히 눈꽃으로 보이지 않는다면 모션 미화 전에 FAIL과 원인 보고.
- **2C-3**: 동일 G2에 B/C0/C1 복원, 실제 앞뒤 가림과 고정 시간 10초 이상 영상, reduced-motion, 모바일 성능 측정.
- **2C-4**: 결과를 한국어로 보고하고 사용자+ChatGPT에게 미적 승인 요청. 본 실험이 곧 실서비스 준비 완료라는 뜻이 아님.

**중단/미달 보고**: 문장 생성 또는 원문 provenance 상실, 새 일기에 의한 anchor 대량 재배치, 미래 ghost 표시, 같은 날짜 높이 증가, 160px에서 완성 눈꽃 불인지, 장시간 멈춤/저성능, 기하가 6갈래가 아닌 경우. 원인을 설명하고 사용자의 다음 미적 결정을 기다린다. 오류가 있더라도 이미 완성한 산출물과 코드 삭제 금지.
