## 0. 무엇이 달라졌나: Gate 2C 결과와 사용자 미감 피드백

**Gate 2C Claude Code가 사용자에게 전달한 결과(직접 코드·이미지 검증 전):**

- G2 = 대표 나선(anchor) + 자연스러운 실제 원문 일부 구절 반복(echo) + 미래 슬롯 원장. 사용자가 원한 밀도 개선을 달성했다는 구현자 평가.
- 15일 기본: 대표 202 + 반복 335 = **537** 그린 글자, 160px 잉크 비율 **2.6%→7.1%**, 큰 줄기 균형 **0.42→0.95**.
- 15일 초단문: 대표 39 + 반복 452 = **491**, 160px 잉크 비율 **0.5%→7.3%**, 균형 **0.27→0.94**. 동일 짧은 표현 반복이 20여 번에 달할 수 있음.
- 성장/원문: 첫 작성일 새 대표 글자 1개 이상이라는 엔진 테스트 통과, 미래 위치 예약, 수정/삭제 시 다른 일기 anchor 유지. 그러나 **1일은 열린 1/15 높이에 총 2개 슬롯, 정면 보이는 글자 1개**로 조형 실패. **같은 날 +2에서도 1일 가시 새 대표 글자 0개**.
- 중심 **반경 28 이내는 비어 있음**. 36→28로 줄였지만 중앙에 정교한 결정 코어가 없고 가지 접합부가 글자 덩어리처럼 보인다는 지적.
- 대표 나선 최대 24자, echo 상한 640자(연구값). 긴 글 15일 G2의 가시 글자 수는 이전 G0보다 줄었음(보고: 541 vs 613).
- DPR2·CPU1×·375×812 단일 작품: 기본 B 33.7fps / C0 32.6 / C1 30.9; 초단문 B 35 / C0 35.3 / C1 32; 긴 글+2 B 31.1 / C0 32 / C1 **29.9(미달)**, 개별 회차는 더 낮을 수 있음. GPU 없는 headless 결과라 불확실성이 크고 앱인토스 실기기 미검증. CPU4× 편차 큼.
- 회귀 58개, 새 테스트 12개 PASS지만 이는 시각적 품질 승인 아님. 기존 \`glyphLayout.ts:193\` 타입 오류와 \`check:syntax\` Windows 경로 버그는 기존 문제.

**사용자의 새 미적 평가 [이번 단계의 최우선 디자인 입력]:** 실루엣을 글자로 채우는 것은 가능해졌지만 **중앙에 비어 있는 느낌**, **전반적 결정 디테일 부족**, **일정한 반지름의 원통형 나선이 독립된 글자 덩어리처럼 보이는 문제**가 남음. 여러 문장 나선이 각 축에서 **서로 다른 반지름/위상/깊이**로 얽히고, 빛의 느낌도 다양하면 좋겠다는 방향.

**앞서 생성한 콘셉트 이미지에 대한 주의:** 복잡한 입체 눈꽃의 분위기·밀도·결정 연결성은 **아트 레퍼런스**일 뿐, 이미지 속 투명 리본/별/잎/광선이 실제 제품에서 허용된 렌더링 재료라는 뜻은 아님. **실제 눈꽃은 출처가 검증되는 사용자 원문 글자의 렌더링만**으로 구성한다. 데이터에 없는 추가 문장·윤곽선·광채 오브젝트·떠다니는 별 장식 금지.

## 1. Gate 2D의 목적

**[실험]** 이미 개선한 G2의 밀도·원문 provenance·배치 안정성을 보존하면서, **새 글자를 무턱대고 더 추가하지 않고** 동일한 대표/echo 글자들의 세계좌표·반지름·깊이·위상·교차 구조를 재설계해 다음을 개선한다.

1. 15일에서 중심을 채운 **작고 정교한 육각 결정 코어**와 여섯 큰 줄기, 36개 작은 가지의 구조적 연결.
2. 각 줄기가 '동일 굵기의 튜브 6개'처럼 보이지 않도록 **가변 반지름과 다중 나선 레이어** 적용.
3. 정지 375px 기본 크기와 160px 도감에서 **멀리서 눈꽃 결정으로 보이고**, 확대하면 글자들이 서로 다른 깊이로 얽힌 조형이 보이게 함.
4. 1일차가 한두 글자처럼 보이는 문제를 **성장 정책을 몰래 바꾸지 않고** 복수 방식으로 검증.
5. DPR2 성능 30fps 경계 문제를 악화시키지 않으며 저비용 최적화를 함께 검증.

**[하지 않는 것]** 최종 B/C0/C1/C2 선택, 미확정 12월 목표 일수 확정, 실서비스 \`GraphicArtwork\`/홈/작성/도감 변경, 제품 색·서체 확정, 로컬 미커밋 원본 삭제, commit/push/PR.

## 2. 디자인 불변 조건 [확정]

- **고유 \`entry_date\` 수가 월간 성장 일수 U**. 같은 날짜 여러 기록은 U 증가 0, 열린 부분의 글자 변화만. 삭제로 마지막 일기 제거 시 U 감소. 연구의 15일은 일반 달 검수 fixture이며 2026-12 특별 목표는 별도 보류.
- **실제 아래쪽부터 위쪽까지 성장**. 아직 열리지 않은 중심/상단 코어 및 가지 윤곽·ghost를 보여주지 않음. 반쪽 glyph 0.
- **큰 축 6개, 60° 간격의 일관된 방사대칭**. 가지 수·길이·세부 텍스트 분포는 연구 범위 내 조정 가능하나 '여섯 갈래 눈꽃 인지'는 유지. 하나의 꽃이 전체 회전하는 것은 금지.
- **글자는 실제 일기 원문에 귀속**. 기존 G2 anchor의 연속 원문 순서 및 안정 slot ledger. echo는 원문 일부 자연 구절을 source offset/copyIndex로 추적한 범위에서만 반복.
- **anchor 우선권**: 새 기록 등장·수정/삭제에서 다른 기록의 anchor identity/slot/key를 보존. echo는 필요한 곳을 양보할 수 있음. **실험 variant 간 좌표 재설계**는 허용하나, 한 variant 안에서 시간이나 데이터 상태에 따라 기존 anchor가 임의로 이동하면 실패.
- **입체 회전**: 각 줄기·가지 자기 로컬 축의 나선 회전, 실제 z-depth와 culling/occlusion. 180° 글자 반전, 가짜 복제 그림자 금지.
- **정지 미감 우선**. 리본 띠·눈송이 장식·표면 메쉬·별 파티클·새로운 자체 광택을 추가해 '예뻐 보이게' 하는 지름길 금지. 글자 자체의 명도 변화(C0/C1/C2)는 연구 가능.
- **접근성**: reduced-motion → 시간 연산이 멈춘 정적 작품; 그래픽 실패 시 정적/저비용 대체 가능. 원문 읽기와 편집은 일기 목록/상세에서 보장.

## 3. 개발 시안 구조 — 한 번에 모든 효과를 섞지 않는다

| 이름 | 구조 | 비교 목적 |
|---|---|---|
| **D0** | 기존 Gate 2C G2 | 기준: 글자 수·비용·형태 |
| **D1** | G2 글자량 유지 + **중심 코어/가지 연결만 조정** | 중앙의 빈 공간 해결이 실제로 미감에 주는 영향 |
| **D2** | D1 + **가변 반지름/나선 2~3층의 교차·깊이** | 원통형 줄기 느낌이 사라지는가 |
| **D3** | D2 + **깊이에 반응하는 C2 shimmer** | 빛이 결정 표면을 스치는 생동감 추가 가치 |

**매우 중요:** D0/D1/D2의 시각 비교는 **같은 dataset·고유날짜·동일 seed·카메라·고정 시각·색/서체**로 실시. 주요 대조 이미지에서는 가능하면 글자 instance 총수도 G2와 동등하게 유지. core에 글자를 넣는 과정에서 다른 영역에서 옮겼다면 **원래 위치 글자 감소**를 metrics로 보고; 새 echo 인스턴스가 추가된다면 비교가 '배치 개선'뿐이 아니므로 별도 표시. D3는 D2의 모든 glyph position, occlusion, count를 동일하게 하고 **명도 함수만 변경**.

### 3.1 D1: 글자로 만든 작은 육각 코어

- 목표는 중심부를 꽉 채운 단색 덩어리가 아니라 **6방향으로 연결되는 한두 겹의 정돈된 육각 관계**를 만들기. 중심부의 작은 음영/네거티브 스페이스는 허용.
- 예전 '반경 28 전면 제외' 대신 **육각 링/연결 브리지 슬롯**을 중심에 추가하는 *연구안*. 단 **새 선형 outline/polyline을 직접 렌더하지 않음**. 실제 문자의 3D 나선이 육각 관절/다른 큰 축을 따라 궤적을 형성할 때만 육각이 보여야 한다.
- 코어 역할의 echo strand는 main axis의 영구 예약(anchor) 충돌 금지. 앞면 글자 중첩이 지나치게 많으면 링 수를 줄이고 각 링 간 depth/phase를 조정. 사용자 원문을 속여서 화려하게 만드는 새로운 글자는 없음.
- 2×/3.2×에서 중앙에 실제 글자가 보이고, 1×/160px에서 전체 결정의 핵이 식별되어야 함. 중심 글자수, 잉크 비율, 과밀·가림·빈 구멍 크기를 기록.
- **중앙 코어는 초기 1~5일에 선행 노출되면 실패**. 동일한 전역 아래→위 reveal을 반드시 따름.

### 3.2 D2: 반지름이 변하는 3D 나선과 교차

- 현재 일정 반지름 helices를 axis상의 s에 따른 부드러운 \`r(s)\`로 확장. 예시 \`r(s)=rBase + a*envelope(s) + b*localAccent(s)\`. 실제 envelope은 C1 연속이며 끝단/접합부에서 끊기지 않게 함; \`r(s)\`는 언제나 양수/안전 범위.
- 동일 main axis에 **2~3개 track 후보**를 겹치되 원문 서로 다른 구절을 가진 독립적인 연속 strand. track별 \`r_i(s)\`, \`phase_i(s)\`, \`z_i(s)\`를 결정적 seed로 분산.
- 3D 위치 예: \`P_i(s,t)=A(s)+r_i(s)cos(theta_i(s,t))N(s)+r_i(s)sin(theta_i(s,t))Z(s)\`. 각 axis local tangent/normal/depth basis는 기존 실제 구현을 재사용하고, 반지름이 바뀌더라도 글자의 앞뒤 culling·occlusion 계산 일관.
- **읽기보다 조형 우선**이나 anchor의 실제 글자 순서·연속 구간은 유지. 완전히 랜덤하게 문자마다 r/phase를 흔들어 독해 가능한 물리적 띠를 파괴하면 실패.
- 주요 줄기와 가지의 교차부는 두 나선의 깊이를 교대로 통과하도록 연구하되 **가짜 교차선, 텍스처 리본, 서로 다른 일기의 텍스트 합성**은 금지.
- 밀도가 160px에서 한 점으로 뭉개지지 않도록 과한 교차는 collision/aliasing 패널티. 코어/가지 접합부/바깥 첨단에 각각 다른 목표 반지름을 주어 '고무줄처럼 균일한 굵기'를 줄인다.
- 하나의 축에 여러 strand가 들어갈 수 있고 하나의 entry가 여러 연속 조각으로 분할될 수 있음. **기존 source range/copyIndex provenance는 유지**.

### 3.3 D3: C2 반짝임 [추가 연구, 미승인]

- C0: 기존 일부 앞면 글자 +10% 밝기. C1: 기존 일부 글자 −28%→원래 색으로 회복. B: shimmer 없음. **기존 3종을 유지**.
- C2(새 시안): 3D 깊이·앞면 방향·국소 조명 벡터를 이용해 **앞쪽에서 특정 각도로 회전해 들어오는 글자만 부드럽게 밝기가 증감**하는 단순한 함수. 프레임마다 무작위 선택, 화면 전체 한꺼번에 점멸, 눈꽃 전체를 훑는 과한 인위적 플래시 금지.
- C2는 **글자 자체의 현재 색/alpha/명도만 수정**, 별 파티클/halo/outer glow/추가 canvas 오브젝트 없음. 글자와 세계좌표·occlusion은 D2와 픽셀 기반(색 제외)으로 동일. 밝기 변화 범위·가시 비율·최소 대비·프레임별 값 별도 기록.
- D2 B/C0/C1/C2를 비교할 때 C2가 기존 C1보다 '좋다'고 개발자가 임의 채택하지 않음. 취향 판단은 사용자의 동영상 시각 검수에 보류.

## 4. 첫날 씨앗: 별도 Geometry Gate (현재의 숨은 물리적 제약)

**현재 G2는 첫날 U=1에서 전역 세로 공개 높이가 1/15이고 그 안에 슬롯이 단 2개**. echo를 더 반복해도 물리적으로 배치할 자리가 없고 같은 날 +2는 보이는 새 대표 글자가 0개. **중앙 코어·15일 완성 눈꽃을 개선해도 이 문제는 자동 해결되지 않는다.**

세 가지 독립 연구안을 **기존 G2와 따로 비교**:
- **S0(대조)**: 동일 1/15 높이, 기존 슬롯 2개·가시 1개.
- **S1(권장 우선)**: **전역 성장 높이 1/15 그대로**, 화면의 아래쪽 열린 영역에 짧은 날개/분기 조각과 로컬 나선 슬롯을 추가해 최소한 '결정 씨앗' 같은 조형을 생성. 6갈래 완성형의 축/문자 질감과 연결되어야 하며 미래 영역/중심 코어 미리 보기 불가. 한 글자라도 새 record가 보일 공간을 우선 예약. 이로 인해 15일 완성 형태가 엉뚱하게 변형되지 않아야 함.
- **S2(연구용 대조, 사용자 승인 전 불채택)**: 첫날 \`reveal(U)\` 높이 곡선을 **비선형**으로 여는 대안. 아래→위 성장·날짜당 1회 증가·0일 공백 규칙은 유지할 수 있으나, 현재 1일=1/15 선형 성장 규칙과 달라짐. 따라서 **별도 시안·명시된 높이 비율**로만 구현하고 사용자 승인 전에 실제 정책에 적용하지 말 것.
- **S3(비교/보류)**: 첫날은 매우 작은 눈꽃 조각으로 보이도록 받아들이는 것. 그 경우 1일 same-day 추가의 변화 0은 UX 결함으로 남기 때문에 저장 성공 표시는 별도 UI에서 보완해야 한다(앱 UI 채팅과 조율; 이 Gate에서 제품 UI는 수정하지 않음).

**첫날의 평가 지표**: 375px 정면 정지 0°, 회전 0~10초 동안 보이는 글자 최소/최대, 총 수용 슬롯, 한 글자의 분명한 조형적 그룹 여부, 같은 날 +2 시 새 일기 실글자 가시/대체 echo 수, 노출 높이, 160px 축소. 목표 미달을 측정으로 숨기지 않는다. 같은 날짜 기록이 무제한일 때 모든 새 문자가 반드시 보인다는 불가능한 보장 금지.

## 5. 성능: 조형 증가 전에 측정 및 저비용 개선

Gate 2C의 장점인 원문별 결정적 배치·React 매 프레임 0회·Layout 0ms는 유지. 이전 gate 기준 약 500~550 glpyhs/프레임에 준하는 부하가 이미 DPR2 CPU1×에서 30fps 근처. 이번 연구에서 글자 수·그린 pixel 면적·drawImage 호출 수가 늘면 위험.

- **첫 단계:** 기존 G2 375×812/DPR1·2/CPU1×, 10초×3회 측정 재현, FPS median, min/percentiles, frame duration p95/p99, drawImage 호출·실제 렌더 glyph 수, changed pixels/overdraw, canvas 크기·캐시 히트, JS execution/paint 비용 분석. CPU4× headless는 별도 참고지표.
- **기하 비교를 위한 공정성:** D0/D1/D2 동일 fixture에서 가시 글자 수/실제 drawImage 횟수, 각 track의 depth occlusion 변화, CPU 시간을 함께 보고. 더 예쁜 그림이 더 느릴 경우 tradeoff를 숨기지 않는다.
- **최적화 연구 [후보]**: glyph atlas/색상 변형 캐시 공유, 축/깊이 정렬 메모이제이션, 고정 시점 glyph precomputation, 과잉 overdraw/culling 전처리, 정적 도감 타일 별도 저비용 스냅샷. 실제 효과가 없는 최적화는 채택하지 않음.
- **목표(연구)**: 단일 D2/D3 375px DPR2 CPU1× **median 30fps 이상**과 60fps 지향, 또한 재현 가능한 **30fps 미만 회차를 정확히 보고**. 목표 경계선에서 미달 시 FAIL/보류. **실기기 Apps-in-Toss WebView FPS가 검증되기 전 제품 성능 승인 금지.**
- **실기기 수집 가능 시** 실제 Android WebView/Apps-in-Toss, 가능하면 iPhone WebView에서 15일 기본·초단문·long, B/C2, 배터리 저전력/발열/가림/메모리 결과. Claude Code가 현재 디바이스에 접근할 수 없다면 접근 불가로 보고하고 기기 테스트 재현 지침 제공. 가상으로 실기기 수치 생성 금지.
- 전체 장면 스냅샷/도감 카드에서 모션이 정지한 경우 **불필요한 RAF 루프 종료** 검증. 매 프레임 React 리렌더·DOM glyph 정렬 금지.

## 6. QA와 디자인 통과 기준

**전제 통과(자동)**
- 각 entryId의 anchor source range·원문 순서 보존. echo 각 glyph의 source offset/copyIndex 추적. 반복은 실제 일기로 집계하지 않음.
- 같은 입력과 stable seed → 동형태/위상/글자 IDs. 입력 순서 변경/날짜 추가/수정/삭제/어제 추가에서 다른 기록 anchor의 slot 안정.
- 0/1/3/5/8/15일을 비롯한 모든 날짜에서 미래 코어/ghost 0, 경계 위/반쪽 글자/반전 글자 0. 같은 날 추가 높이 변동 0.
- 6-fold 대칭과 36가지 구조를 유지한 것을 검증하되, **실제 글자 분포의 미세한 비대칭은 허용**; 해당 구조가 가시적으로 보이는가 별도 확인.
- 앞/뒤 culling과 앞 글자에 의한 뒤 글자 가림 보존, 문자 자체 광도 변화만. \`prefers-reduced-motion\` 정지 및 동일 시점 결정성.
- G2 vs D1 vs D2 비교에서 **어떤 glyph들이 다시 배치되었는지**, 실제 그려진 수·anchor/echo 비율·원문 coverage를 JSON 보고. 긴 기록이 이전보다 덜 보인다면 수치와 이유 설명.

**사용자 시각 승인(자동 PASS로 대체 불가)**
- D0/D1/D2 15일 완성형, 모바일 기본 크기와 160px 도감의 시각적 차이.
- 중심: 구멍과 과밀의 균형, 실제로 '육각 결정의 코어' 같은가, 단순 글자 덩어리인가.
- 팔/가지: **여러 글자들이 교차하여 하나의 눈꽃**으로 보이는가, 일정한 원통 여섯 개를 붙인 형태인가.
- 정지 상태의 아름다움과 10초 이상 회전 영상에서의 3D/글자 부유·반짝임 감.
- 첫날 S0/S1/S2 정면/동작 비교. S2는 최종 승인과 별개.
- C0/C1/C2 중 효과 가시성이 적절하고 과한 깜빡임 없이 조용한가.

**중단/실패 분류**: D2로 바꿔도 코어가 한 덩어리, 160px에서 6갈래 인지 불가, 미래 중심 미리 노출, 안정 ID 분실, 동일일 진행 높이 증가, 1일 여전히 1~2자, C2가 네온/점멸이 됨, DPR2 실제 계측 미달 → 해당 실패와 재설계 옵션을 한국어로 즉시 보고. 미완성 상태로도 현재까지의 비교 이미지는 남긴다.

## 8. 실행 순서와 보호 경계

**Gate 2D-0: Baseline & measurability** 기존 로컬 G2 엔진/README/metrics 열람. 15일, 1일 스냅샷·성능 재현. 초기 글자 수와 view 기준 고정.

**Gate 2D-1: Core/branch geometry D1** central hex-core과 가지 연결만 구현, 실제 출처 있는 glyph로 렌더. 정지 비교에서 중심 과밀/고립이 해결되지 않으면 다음 단계 앞서 원인 리포트.

**Gate 2D-2: Variable radius/interlacing D2** D1 위에 track별 r(s)/phase/z를 계산해 실제 3D 가림·입체감 구현. 너무 정돈이 안 되면 D1를 수정하는 것이 아니라 비교 실패로 보고.

**Gate 2D-3: Seed S0/S1/S2** 완성형의 기하와 별개로 첫날 아래 영역만 실험. S2 비선형 reveal은 개발 내부에만 존재하고 사용자 승인 전 실제 정책으로 채택하지 않음.

**Gate 2D-4: C2 & perf** B/C0/C1/C2 같은 D2 geometry, 실제 프레임 성능/메모리/정지 폴백. 필요시 Render optimization 후보 1~2개 비교하고 향상 여부를 근거로 설명.

**Gate 2D-5: QA & handoff** 산출물 정리, 사용자 시각 승인이 필요한 핵심 쟁점 3~5개 제시. 누락/불합격 케이스를 과장없이 명시. 이미지나 영상만으로 코어가 3D 구현됨을 증명할 수 없으므로 깊이·가림 값 테스트 필요.
