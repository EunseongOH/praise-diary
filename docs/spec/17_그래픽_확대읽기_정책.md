# 17. 그래픽 확대 읽기 정책

## 목적
- 사용자가 월간 그래픽을 확대해서 감상할 수 있어야 한다.
- 확대 시 같은 일기에서 나온 글자들이 가까운 위치에 모여, 일부 문장을 실제로 읽을 수 있어야 한다.
- 그래픽의 성장 높이는 **작성 일수** 기준으로 유지하고, 같은 날짜의 추가 일기는 높이를 늘리지 않는다.

## UX 정책
1. 홈/월 상세에서 그래픽을 누르면 `graphic` 화면으로 이동한다.
2. `graphic` 화면은 별도의 확대/축소 버튼 없이 기본 크기로 감상할 수 있다. 필요할 때 두 손가락 제스처로 확대·축소한다.
3. 화면 조작 요소를 추가하지 않고, 제스처에 따라 1.0x ~ 3.2x 범위에서 배율을 조절한다.
4. 확대된 그래픽은 영역 내에서 손가락으로 이동하며 감상한다.
5. 확대 동작을 알려주는 보조 문구는 노출하지 않는다. 이용자가 몰라도 되는 기능이며 필요하면 자연스럽게 발견하게 한다.

## 그래픽 배치 정책
- **성장 규칙**: 기록 날짜 수에 따라 아래에서 위로 채워진다.
- **추가 일기 규칙**: 같은 날짜의 추가 일기는 높이는 유지하고, 이미 열린 영역 안의 글자 밀도만 늘린다.
- **일기 단위 고정성**: 같은 일기 텍스트는 인접한 슬롯들에 순서대로 배치한다.
- **안정성**: 이전 일기의 슬롯은 이후 일기 추가로 크게 흔들리지 않도록, 엔트리 순서대로 슬롯을 이어서 점유한다.

## 구현 메모
- `assignDiaryGlyphs()`가 눈꽃 슬롯 집합에 대해 일기별 연속 슬롯을 할당한다.
- 각 일기는 `extractDiaryGlyphs(body)`를 통해 정제된 글자 배열을 갖는다.
- 슬롯은 하단 우선(y 내림차순)으로 정렬해 초기 일기들이 아래쪽에 배치되도록 한다.
- 현재는 눈꽃에 우선 적용, 붉은 양/해 그래픽에는 후속 적용.
