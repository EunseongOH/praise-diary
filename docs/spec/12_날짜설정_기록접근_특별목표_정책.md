# 칭찬일기 — 날짜 정책·내 기록 접근·12월 특별 목표 정합성 v1.6

> 2026-11-21 · 확정/제안/보류 구분 · 기존 01/04/09 문서를 대체하지 않고 상세 규칙을 보완.

## A. 12월 특별 목표

**[확정]** 2026년 12월에는 출시일에 맞춘 정규(15일)와 다른 특별 목표를 제공한다. **정확한 목표 일수는 출시일 확정 전까지 미정**이다. 2027년 1월은 정규 15일을 목표로 한다.

- `MonthCatalog.target_days`에 월별 값 저장. 클라이언트에 12월 목표를 하드코딩하지 않음.
- 12월 목표가 미정이라도 그래픽 원형/진행 개념은 설계 가능. 단 사용자에게 아직 확정되지 않은 12월 수치를 노출하지 않는다.
- 출시일 확정 시 달성 가능 일수, 첫 출시 시점부터의 기간, 이월 작성 1일 규칙을 고려해 설정.

## B. 하루가 바뀌는 시간

**[확정]** 기본 KST **00:00**, 사용자별 변경 가능. 사용자는 서비스에서 '오늘'과 '어제'의 날짜 귀속을 개인 생활 패턴에 맞게 바꿀 수 있다.

**[제안]** 선택 옵션 00:00, 01:00, 02:00, 03:00, 04:00 정각. 추가 세부 단위 여부는 UX 테스트에서 결정.

### 날짜 계산 규칙

- 기준 시간대: KST(초기 MVP). 설정값은 `day_boundary_hour: 0..4` 같은 사용자 필드로 저장 [스키마 제안].
- 사용자의 현지 KST 시각에서 **시각이 `day_boundary_hour` 미만이면 서비스 날짜는 전날**, 그 외에는 달력 당일. 경계 0시는 언제나 달력 당일.
- 신규 일기 기본값 `entry_date = serviceDate(now, userBoundary)`; 어제를 택하면 `entry_date = serviceDate - 1 day`.
- 저장된 `entry_date`는 귀속 날짜로 보존. `created_at`은 실제 서버 저장 시각. 기존 일기를 개인 설정 변경 때문에 소급 변경하지 않음.
- 일수·월별 그래픽·도감은 저장된 `entry_date` DISTINCT로 계산.
- 예를 들어 **1월 1일 01:00**: 기본 00:00 경계 → 1월 1일 일기. 03:00 경계를 지정한 경우 → 12월 31일 일기.

### 작성 중 설정·시간이 바뀌면

- **[확정]** 이미 선택된 일기의 날짜와 본문을 자동 변경하지 않고, 작성 중인 세션의 저장 유예를 제공한다.
- **[보류]** 몇 시간까지 무중단 저장을 허용할지, 장시간 방치 후 복원 시 어떤 날짜를 제안할지. 서버 `writing_started_at`과 최초 선택한 `entry_date`로 유효성 검증.
- 사용자별 설정을 바꿔도 **이전 일기 기록 날짜는 바뀌지 않는다**는 사실을 설정 화면에서 설명한다.

### 사용자에게 보이는 정보

**[확정]** 작성 화면 상단에 실제 귀속일을 상시 표시. 토스트는 날짜가 바뀌거나 예상과 다를 때의 보조 안내로만 사용.

- D-01: `11월 21일의 칭찬`.
- 설정상 경계로 인해 달력 날짜와 달라지는 경우: `11월 20일의 일기로 기록돼요.`
- 저장 완료: 필요한 경우 `11월 20일의 칭찬을 남겼어요.`
- 설정: `하루가 바뀌는 시간` / 설명 `늦게 잠드는 편이라면 하루가 끝나는 시간을 늦출 수 있어요.`
- 날짜 변경 설정 저장: `앞으로 쓰는 일기부터 적용돼요. 이미 남긴 기록의 날짜는 그대로예요.`

카피는 확정 의도를 반영한 초안으로, UI Writing 단계에서 자연스러움을 재검토.

## C. 미래 월의 미공개 테마

**[확정]** MVP의 신규 작성 날짜는 오늘·어제뿐이므로 **미래 월 일기 작성 기능이 없다**. 따라서 미래 테마가 준비되지 않은 상태의 일기 작성 플로우는 요구하지 않는다.

- C-01 미래 월 미공개: 잠긴 카드 → C-03 잠금 설명 → 낮은 위계의 C-04 아이디어 제안.
- 해당 월이 실제 도래하기 전에 테마 에셋과 월별 규칙을 준비/배포하는 것은 출시 운영의 체크리스트. 일기 화면에 별도의 가짜/임시 그래픽을 만들지는 않는다.
- 연말/월말 '어제' 작성과 세션 유예로 **이미 지나간 월의 그래픽**은 갱신될 수 있다. 이는 미래 월 작성과 별개다.

## D. 꺼내보기와 내 기록 목록의 독립성

**[확정]** 꺼내보기는 10편 누적 최초 달성시 영구 해제되는 **랜덤 회고 기능**. 일기 목록 조회/수정/삭제는 잠금과 무관.

권장 진입점:
- H-01 홈에서 ‘내가 남긴 칭찬 보기’ 같은 **작은 텍스트 액션** → L-03 전체 일기 목록.
- C-02 월별 그래픽 상세에서 ‘이달의 칭찬 보기’ → L-03 해당 월 필터.
- L-01 꺼내보기 해제 후 랜덤 편지를 열고 L-04 상세에 접근하는 기존 경로 유지.

**그래픽 터치 규칙 [제안]:** 단순 탭은 그래픽 확대 감상(G-03). 길게 누르기를 목록 접근 수단으로 추가할 수는 있지만, 발견하기 어렵고 드래그 감상과 충돌하므로 **유일한 목록 진입점으로 쓰지 않음**.

**빈 목록:** 첫 일기 이전에도 홈의 목록 링크를 눌러 진입할 수 있고, ‘아직 남긴 칭찬이 없어요. 첫 칭찬을 남겨볼까요?’와 작성 CTA 표시 [제안].

## E. 정합성·QA

1. 11/21 00:30, 기본 자정이면 11/21 일기로 표시한다.
2. 11/21 00:30, 개인 설정 03시라면 11/20 일기로 표시한다.
3. 위 어느 경우에도 날짜 표시와 저장된 `entry_date`가 일치한다.
4. 23:59에 시작해 00:15에 완료해도 세션의 본문/날짜를 보존한다(저장 유예 범위는 미정).
5. 기존 일기 날짜가 설정 변경으로 소급 이동하지 않는다.
6. 지난달 마지막 일기를 다음 달 초 '어제'로 기록해도 지난달 그래픽을 갱신한다.
7. 미래 월을 선택해 새 일기를 만드는 경로는 없다.
8. 꺼내보기 미해제 상태에서 홈 → L-03 → L-04 수정/삭제가 가능하다.
9. 홈 그래픽 감상과 기록 목록 액션이 서로 구분된다.
10. 12월 특별 목표 숫자가 출시일 결정 전에는 확정된 값으로 노출되지 않는다.
