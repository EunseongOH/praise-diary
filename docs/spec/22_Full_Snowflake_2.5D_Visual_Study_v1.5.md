## 0. 목표와 경계

[사용자 방향 확정] 한 줄기의 B(나선 회전+미세 부유), C(B+은은한 글자 반짝임)를 선호한다. 다만 여섯 큰 줄기 및 작은 가지를 가진 **완성형 눈꽃**에서 무엇이 아름다운지 아직 확인하지 못했으므로 실제 2.5D 눈꽃 전체를 조형하고 동작 영상을 비교한다.

[이번 실험] 새 개발용 `/__dev/full-snowflake-study`를 만들고 같은 원문/입체 구조/성장 높이에서 B, 기존 C 및 C의 미세한 대안 효과를 비교한다. 첫 검토 대상은 **글자 자체로 구성된 눈꽃 실루엣**이며, 여섯 방향으로 같은 원문/글자 묶음을 복사하는 눈꽃은 실패.

[하지 않음] 실제 `GraphicArtwork` 및 홈/도감/일기/상세 화면 교체, B/C 미적 채택, 2026년 12월의 특별 목표 확정, 색·폰트 최종 선택, 실서비스 배포, 기존 스터디 산출물 교체, 커밋/push/PR.

## 1. 제품의 확정 원칙

1. 사용자 원문 또는 본 연구의 가상 일기 문장만으로 문자의 나선을 만든다. 가짜 문장/장식적 별·점/눈꽃 외곽 선/네온/글로우 금지.
2. **한 줄기=한 일기 아님**. 하나의 줄기/작은 가지에 여러 일기 구간이 들어갈 수 있고, 같은 일기의 연속 구절은 실제 순서대로 이웃한 위치에 배치.
3. 나선형 문자가 각 줄기/가지의 **로컬 축**을 3D로 감싼다. 글자 앞뒤 가림이 실제로 바뀌며, 글자 그림자 복제로 깊이 표현 금지.
4. **서로 다른 `entryDate` 수만** 아래→위 성장 높이를 결정. 같은 날짜 추가 일기는 기존 높이만 채움. 0일=미래 윤곽/ghost 없음. 성장 경계에 반쪽 글자 금지.
5. 사용자 선택의 핀치 확대/팬은 실서비스에서는 숨겨진 기능. 내부 비교용 배율/각도 도구는 허용되지만 실서비스 UI에는 추가하지 않음.
6. `prefers-reduced-motion`에서는 자동 회전·부유·반짝임을 모두 중지.

## 2. 눈꽃 형태·세계 좌표 (연구 출발값)

- **큰 줄기 6개가 중심 기준 60°씩 방사**, 각 큰 줄기에서 좌우 3쌍의 작은 가지 분기(총 6개 큰 줄기 + 36개 작은 가지/첫 모형). 숫자는 테스트용 기준이지 최종 원화 확정이 아님.
- 모든 줄기/가지는 3D 로컬 좌표계를 가진다. 각 축 접선 `a`, 화면 XY 안에서 축에 수직인 `n`, 화면 깊이 `z`를 기준으로 `P(s,t)=axis(s)+r cos(theta)*n + r sin(theta)*z` 형태의 나선을 만든다. 기존 로컬 Helix/Snowglobe 엔진의 실제 API와 기하 구현을 읽고 재사용·확장한다.
- **축의 방향과 눈꽃 전체 카메라는 고정**. 여섯 축의 글자 나선만 각자 자기 축을 기준으로 아주 천천히 회전한다. 눈꽃 전체를 돌리거나 여섯 개 단일 나선 컴포넌트를 복붙해 독립적으로 흔드는 방식 금지.
- 글자 자체가 눈꽃의 형태. 눈꽃 실루엣을 선으로 먼저 그리고 글자를 올리거나 미래 부분을 반투명으로 미리 보여주지 않는다. 중심부 과밀·가지 불연속·빈 구멍은 명확히 보고.
- 고정 카메라와 충분한 관찰 공간으로 **모바일 375px 기본 상태**에서 6갈래 눈꽃 인식이 가능한지 평가. 320·430px과 도감용 160px 축소 정지 화면도 검증.
- 반대편/옆면 거울 글자와 세로 막대 잡음을 제어하고 앞면의 연속된 실제 구절은 2×/3.2×에서 일정 부분 독해 가능하도록 설계.

## 3. 실제 원문을 여섯 줄기 및 가지에 분배 (연구안)

- `19번 명세 부록 A`의 `demo-01~15`, `extra-1/extra-2`, `base/short/long/mixed` 가상 fixture만 사용. 별도 문장 생성/외부 일기 사용 금지.
- 데이터 경로: `entryId -> original excerpt index range -> axisId -> helixTrackId -> stable glyph slot`. 한 일기를 여러 축에 분배할 수 있지만 **서로 다른 원문 구간**을 사용하고 텍스트 복제는 금지한다.
- S(축방향 구간 배치) 또는 R(반지름별 중첩) 중 **최종안 결정 전**. 이번에는 글자 충돌을 최소화하고 reading lane을 연결하는 **단일 공통 geometry**를 B/C 세 시안에 고정해 모션의 차이만 비교. 구성 방식과 이유를 보고. S 1·3일 같은 날 +2의 0px 변화, R의 과밀 현상은 선행 결함으로 독립 보고.
- 여섯 방향의 활성화 위치는 전역 성장 경계를 따른다. **매일 6개 줄기에 같은 한 문장을 복제하지 않는다.** 해당 날짜의 새 글자가 이미 열린 하단 영역 내 일부 축에만 나타나도 되나 **저장 직후 눈에 보이는 완전한 글자가 최소 1개 추가**되어야 함.
- 고유 날짜마다 글자수·눈꽃 높이가 어떻게 바뀌는지 기록. 초기 1일의 빈약함, 15일 상단의 빈 영역, 짧은 일기에서 실루엣 약화 등을 있는 그대로 캡처하고 부자연스러우면 '미완성'이라 판단.
- 수정/삭제/같은 날짜 추가 후 기존 `entryId`의 축·원문 순서·문자 위치가 가능한 한 고정. 글자 수용량이 모자라면 일부 원문을 표시하지 않을 수 있지만 다른 일기 속에 섞지 않는다. **모든 글자가 보인다는 주장은 금지**.

## 4. 성장·모션 결합

- 연구 fixture의 전역 성장 경계: `top = yBottom - (yBottom-yTop)*min(uniqueDays/15,1)`. 15일은 **실험에만 적용**, 실제 2026년 12월 목표는 미확정.
- 각 글자의 세계 좌표, 카메라 투영 바운드 및 부유 변위를 확인해 허용 영역을 넘어가지 않도록 함. 경계에서 문자 반쪽이 보이지 않도록 **완전 표시/완전 비표시**.
- **B:** 현재 Gate 2A-M의 회전+상관된 미세 부유 그대로; 20초/바퀴 연구값(24초 비교 가능).
- **C0:** B와 동일한 배치·회전·부유 + 기존 +10% 가시 글자 shimmer(단일 줄기에서 거의 안 보였던 기준).
- **C1 [추가 실험안]:** B와 동일한 모든 기하·시간, 앞면의 일부 글자만 **조금 낮은 밝기에서 원래 기준 밝기로 서서히 회복하는 방식**을 비교. 원색·새 글로우·별입자 금지. 기준 명도 변경량과 정규화 방법을 README에 적고, 읽기 가능한 텍스트 대비를 유지. 한순간 대략 가시 글자의 3~6% 이내, 1.8~3.2초의 긴 envelope, 프레임마다 random jitter 금지.
- **B/C0/C1**의 비교에서 다른 것은 shimmer뿐. 같은 snapshot time과 회전 위상, fixture, 로컬 축, glyph 수, 카메라·배경을 사용. C1 채택 여부는 사용자 최종 시각 검수.
- 모든 축이 같은 위상으로 회전하지 않되, 개인 일기의 이웃 글자들은 서로 어긋나지 않도록 상관 부유. 특정 줄기나 중심부가 눈에 띄게 깜빡거리는 현상은 불합격.
- 정지 상태의 눈꽃 인지성이 우선. 예쁜 모션으로 부실한 정지 실루엣을 가리지 않는다.

## 5. 구현 단계·성능

**2B-0 정적 눈꽃:** 먼저 0/1/5/8/15일의 6줄기+가지 전신 캡처 생성. 15일 기본 1×에서 눈꽃으로 보이는지, 글자 밀도·중심·가지 연결이 어색한지 기록.

**2B-1 모션:** 동일한 15일 geometry에서 B/C0/C1의 회전·실제 가림·부유·shimmer를 입힌다. 독립적인 React 글자 재렌더/매 프레임 원문 재토큰화 금지. 단일 clock, 고정 geometry, 글리프 캐시 이용; Canvas2D를 쓰더라도 적합성 검토 필요.

**2B-2 QA/성능:** Playwright Test/가능하면 MCP로 레이아웃·성장/수정삭제·축 가림·모션 비교. 각 시안의 **단일 작품** 기준 모바일 Chromium 375×812, CPU1×/4×, 10초×3회 측정. 3개 시안 동시 보여주는 갤러리 FPS를 실제 서비스 작품 FPS처럼 보고하지 않기. 그린/총 글자 수, 축 수, FPS, frame p95, long tasks, 메모리 가능 시 기록. CPU1× 30fps 이상은 시각 검토 가능한 후보의 연구용 최저 목표, 60fps 지향. 4× GPU 없는 테스트는 불안정할 수 있으므로 실기기 성능 판정을 대신할 수 없음.
- Full snowflake가 CPU 병목으로 실행 불능이면 정지/부분 시안만 남겨도 미완성 원인을 정확히 보고. FPS 개선을 위해 몰래 글자를 삭제하거나 실제 앞뒤 가림 제거 금지.
- `prefers-reduced-motion`과 고정 회전각 모드에서 화면이 안정적이어야 함.

## 7. 반드시 테스트할 것

- axis 6개, twig 36개 구조/글자 가시화 실제 개수 보고; 0일 빈 상태.
- 작성일별 아래에서 위로 성장, 각 날짜 첫 작성 시 최소 1개 가시 글자, 같은 날 +2 높이 불변, 1일 같은 날 추가가 안 보이는 문제 별도 표시.
- 글자 단위 경계 검사(0/45/90/135/180° 및 동적 시간 샘플), 원문 순서·중복 원문 방지, 임의 배열 순서에서도 같은 위치, 수정/삭제 후 기존 글자 안정성.
- 앞뒤 진짜 가림·거울 글자 0·복제 그림자 금지, 2×/3.2× 일부 구절 읽기.
- 같은 시간에서 B/C0/C1의 위치·가림 결과 동일; shimmer만 다름. reduced motion 무반복.
- 정지 160px 타일 눈꽃 인식도·전체 실루엣 균형은 자동 테스트 PASS와 별도로 **사용자 판단 보류**.
- 기존 `glyphLayout.ts:193` 타입 오류·Windows `check:syntax` 버그는 로컬 현재상태 재확인 후 신규 오류와 구분하고 이 Gate에서 무관한 제품 소스 수정 금지.

## 8. 로컬 보호

이전 Gate 2A-M 구현은 사용자의 PC 로컬 작업 트리에 있고 **아직 커밋·push되지 않음**. Claude Code는 `git status --short`로 보호 대상을 확인. 새 명세는 `git fetch origin feat/design-system-prototype` 후 `git show origin/feat/design-system-prototype:docs/spec/22_Full_Snowflake_2.5D_Visual_Study_v1.5.md`로 읽기. `git pull`, `checkout`, `reset`, `restore`, `clean` 무단 실행 금지.

로컬 `src/dev/snowglobe`, `src/dev/multiHelix`, `src/dev/helix`를 실제 열어 API 재사용. 기존 스터디 및 모든 `artifacts/` 원본을 변경하지 않는다. 기존 이슈를 새 실험으로 보완할 수 있어도 **원본 엔진을 파괴적으로 수정하지 말고 신규 adapter/모듈을 만든다**.

모든 보고 한국어. 실서비스와 `GraphicArtwork` 수정, 커밋/push/PR, 색·폰트·12월 목표 확정, C1의 최종 채택 금지.
