# 칭찬일기 — 알림·공통 UX Writing 가이드 v1.5

> 기준일: 2026-11-21. **사용자에게 보여 줄 UI 문구**와 **앱인토스 승인 전에는 발송 불가한 푸시 문구**를 엄격하게 구분. 최종 카피는 사용자 의도에 따른 [제안]이며 동의·사용 여부는 확정 전.

## 1. 제품 언어 규칙

1. 사용자의 행동을 기준으로 설명. 내부 유형·렌더링 상태코드·서버·기능성 메시지 등 기술어 금지.
2. 제목 1개 + 1~2문장 설명 + 동사 기반 주요 CTA. 같은 내용 반복하지 않음.
3. '당신은 더 열심히 해야'/'안 쓰면 실패' 등 죄책감 유발 금지.
4. '오늘'은 사용자가 설정한 하루 경계(기본 자정) 기준의 날짜와 혼동될 수 있으므로 일기 작성일 자체가 중요한 순간에는 정확한 날짜도 표시.
5. '알림을 켜면 더 이상 놓치지 않아요'처럼 보장할 수 없는 주장 금지. 선택한 시각·동의 상태·끄는 방법만 말함.
6. 정보 중심 화면에는 장식용 아이콘/카드/대형 문구를 붙이지 않음.

## 2. N-01 최초 작성 뒤 알림 신청 — **앱인토스 승인된 경우에만 노출**

- **제목:** 하루를 돌아볼 시간을 정해둘까요?
- **설명:** 원하는 시간에 칭찬일기를 떠올릴 수 있도록 알려드려요. 이미 칭찬을 남긴 날에는 보내지 않아요.
- **주요 CTA:** 알림 시간 정하기
- **보조 CTA:** 나중에
- 동의 목적과 실제 발송 내용이 일치할 때만 제공. 최초 저장·그래픽 연출을 감상한 뒤 요청. 거절해도 본래 기능 모두 사용 가능.

### 대안 카피 [제안]

- 간결형 제목: **칭찬일기 알림을 받아볼까요?**
- 설명: **직접 고른 시간에 알림을 받을 수 있어요.**
- 톤 선택은 실제 알림 메시지 템플릿 심사 후 확정.

## 3. N-02 시간 선택 및 동의 [조건부]

| 상태 | 제목 | 설명/피드백 | 행동 |
|---|---|---|---|
| 시간 선택 | 언제 알려드릴까요? | 알림을 받고 싶은 시간을 골라주세요. | 알림 받기 / 취소 |
| 동의 요청 전 | 알림을 받을까요? | 선택한 시간에 알림을 받을 수 있어요. | 알림 설정하기 / 나중에 |
| 설정 완료 | 알림 시간을 저장했어요. | 선택한 시각을 상세 상태로 함께 표기 | 확인 |
| 동의 거절 | 알림은 켜지지 않았어요. | 나중에 설정에서 다시 신청할 수 있어요. | 확인 |
| 기능 미지원 | 지금은 알림을 설정할 수 없어요. | 이용 중인 토스 앱에서 지원하지 않는 기능이에요. | 확인 |
| 일정 변경 실패 | 시간을 변경하지 못했어요. | 다시 시도해 주세요. | 다시 시도 / 취소 |
| 알림 해제 | 알림을 껐어요. | 앞으로 칭찬일기 알림을 보내지 않을게요. | 확인 |
| 정책 미승인 | **알림 관련 화면 자체 비노출** | 이용자에게 '곧 출시'를 반복 노출하지 않음 | 해당 없음 |

**시간 추천 [검증 조건부]:** 오전 8:00, 오후 6:30, 오후 8:30. 21시 이후를 기본 추천 시간으로 내걸지 않음. 직접 시각 선택·대량/단건 발송 방식 결정 전에는 모든 시각 제공 약속 금지.

## 5. 푸시 알림 문구는 아직 '승인됨'으로 취급하지 않음

**공식 앱인토스 푸시/알림 가이드 (2026-11-21 확인)**:
- 기능성 메시지만 가능. 광고·리텐션·재방문 유도 불가. 사용자가 직접 신청했더라도 작성 리마인더가 정책상 승인된다는 보장은 없음.
- 템플릿 검수 및 목적별 수신 동의 필요. 토스 자체 동의 UI는 `Notification.requestAgreement` 기반.
- 공식 안내의 템플릿 예시 제목은 **7자 이내**, 내용은 **25자 이내**, '~요.' 종결 및 이용자 행동 직접 유도 표현 주의.
- 오후 21:00~익일 08:00 야간에는 **대량 발송 지연**; 단건은 가능하나 그 자체가 메시지 정책 적합성 보장은 아님.

따라서 실제 푸시 카피를 확정·발송하지 않고, 승인받은 사용 목적 및 템플릿이 정해지면 그 제약에 따라 별도 설계. **본 문서의 N-01/N-02 문구는 미니앱 내부 설명이지 승인된 푸시 템플릿이 아님.**

## v1.6 추가: 날짜 안내 카피 [사용자 정책 확정·카피 제안]
- **D-01 날짜 표시(항상):** ‘11월 21일의 칭찬’(실제 저장할 날짜를 표시).
- **새벽 경계 설정 때문에 전날로 기록되는 경우:** ‘11월 20일의 일기로 기록돼요.’
- **저장 성공 후 확인 메시지(필요시):** ‘11월 20일의 칭찬을 남겼어요.’
- **S-01 항목명:** ‘하루가 바뀌는 시간’ / 기본값 ‘오전 12:00’.
- **설정 설명:** ‘늦게 잠드는 편이라면 하루가 끝나는 시간을 조금 늦출 수 있어요.’
- **설정 변경 완료:** ‘앞으로 쓰는 일기부터 적용돼요. 이전에 남긴 기록의 날짜는 그대로예요.’
- 실제 기록 날짜를 토스트에만 의존해 전달하지 않고 화면 상단에 지속 표시. 선택한 날짜를 사용자가 모르게 바꾸지 않음.
