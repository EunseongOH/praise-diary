# 칭찬일기 — S-02 전체 기록 삭제 보호 절차 v1.5

> 2026-11-21. **[확정]** 사용자는 모든 칭찬일기 삭제가 실수로 실행되지 않도록 여러 번의 확인을 요구. **[제안]** 3단계 안내·정확한 문구 입력·마지막 의사 확인을 구체 구현.

## 1. 삭제 종류 구분

| 종류 | 수행 대상 | 꺼내보기 해제 | 다른 기록의 영향 |
|---|---|---|---|
| 단일 일기 삭제 | 특정 `entry_id` | 유지 | 해당 날짜 마지막 일기라면 인정일 -1, 그래픽 축소 |
| **모든 칭찬일기 삭제** | 일기 전체 및 파생 그래픽·랜덤 후보 | **유지** | 도감의 기존 그래픽도 빈/초기 상태가 됨 |
| 서비스 데이터 전체 삭제 | 일기·초안·설정·해제 이력 등 사용자 데이터 | **초기화** | 서비스 재진입 시 새 이용 상태. 법적 보존·백업 정책 검토 |

두 전체 삭제 기능을 하나의 CTA로 섞으면 안 된다. 메뉴 구성 자체는 후속 결정 사항이지만 각각의 영향은 분명해야 함.

## 2. 모든 칭찬일기 삭제의 다단계 확인 [확정 방향+구현 제안]

1. **S-02 기록 관리에서 명시적 삭제 항목 선택:** ‘모든 칭찬일기 삭제’. 실수로 터치했어도 이 단계에서 삭제 실행은 금지.
2. **영향 확인 페이지:** ‘작성한 칭찬일기 [n]개와 이 글자로 만들어진 월별 그래픽이 모두 삭제돼요. 삭제한 일기는 앱에서 되돌릴 수 없어요.’ 버튼 ‘계속’ / ‘취소’. 삭제 수는 서버에서 계산.
3. **문구 입력:** ‘계속하려면 모든 기록 삭제를 입력해 주세요.’ 입력창; 정확히 일치하지 않으면 삭제 CTA 비활성화. 앱에 닉네임 기능이 없으므로 닉네임 입력을 새 가입 단계로 강요하지 않음. 닉네임 수집이 도입되면 대체 검토 가능.
4. **마지막 다이얼로그:** ‘정말 모두 삭제할까요?’ 주요 결정을 거꾸로 강조하지 않음. 기본 동작 ‘취소’, 파괴적 행동 명칭 ‘[n]개의 일기 삭제’. 요청 전후 연결·입력 상태 검증.
5. **서버 성공 후:** 완료 표시→홈·도감은 빈 그래픽, 꺼내보기 영구 해제 이력은 유지. 기록 0개면 잠금이 아니라 ‘꺼낼 칭찬이 아직 없어요.’

## 3. UX Writing [제안]

### 영향 안내

- **제목:** 모든 칭찬일기를 삭제할까요?
- **설명:** 작성한 일기와 그 글자로 만든 그래픽이 모두 사라져요. 삭제한 기록은 되돌릴 수 없어요.
- **CTA:** 계속 / 취소

### 확인 문구 직접 입력

- **레이블:** 계속하려면 ‘모든 기록 삭제’를 입력해 주세요.
- **입력값:** 모든 기록 삭제
- **CTA:** 삭제 확인 / 취소

### 마지막 확인

- **제목:** 정말 모두 삭제할까요?
- **설명:** 일기 [n]개와 월별 그래픽을 삭제해요. 이 작업은 취소할 수 없어요.
- **파괴적 CTA:** [n]개의 일기 삭제
- **안전 CTA:** 취소

### 실패 및 완료

- **실패:** 기록을 삭제하지 못했어요. 다시 시도해 주세요.
- **완료:** 칭찬일기를 모두 삭제했어요.
- 모든 단계에서 사용자에게 두려움을 조성하거나 죄책감을 유발하는 과장된 감성 문구 금지.

## 4. 서버 정합성·개인정보 보호

- 요청 전 본인 확인 및 인증된 사용자 상태 검사. 문구 입력 자체만으로 인증이 된다고 간주 금지.
- 기록 총 수를 서버에서 계산하여 마지막 확인과 실제 삭제 건수를 일치시킨다. 동시 수정으로 n이 바뀌면 영향 재확인.
- 요청 중 이중 클릭 방지·중복 삭제 방지. 서버 성공 확인 전 UI에서 결과를 완료 처리하지 않음.
- 서버 삭제는 DiaryEntries·Drafts(포함 여부 결정)·MonthlyProgress/graphic cache·LetterDrawHistory 등 파생 데이터를 하나의 일관된 상태로 갱신. `letter_draw_unlocked_at`은 유지.
- 분석 이벤트/앱 로깅에 실제 일기 원문·사용자 입력 확인 문구를 기록하지 않음.
- 관리자/백업·법적 보존 관련 실제 삭제 시점과 범위는 이용약관·개인정보 정책과 일치해야 함. 데이터가 기술적으로 남아 있다면 '즉시 모든 백업 삭제' 등 보장할 수 없는 문구 금지.

## 5. 필수 QA

1. S-02 클릭만으로 삭제 API 호출 없음.
2. 영향 안내에서 취소 가능.
3. 확인 문구 불일치/공백이면 최종 버튼 비활성화.
4. 정확한 문구 입력 후에도 마지막 확인에서 취소 가능.
5. 서버 삭제 실패/연결 중단 시 성공 토스트 없음.
6. 성공 후 홈·도감·L-03 목록에서 이전 원문 사라짐.
7. 이전에 10개 달성했다면 0개로 삭제 후에도 꺼내보기 해제 이력 유지.
8. '서비스 데이터 전체 삭제'는 별도 영향 고지 및 다른 서버 로직.
