# Claude Code 작업 지시 — Gate 2D Sculptural Snowflake Study

**사용자에게 제공하는 진행 보고·질문·테스트 설명·최종 보고는 반드시 한국어로.** 로컬 미커밋 코드와 기존 산출물 보호가 최우선.

## 0. 이 작업을 하는 이유

Gate 2C(G2)에서 원문 일부 구절 반복(echo)으로 **기본/짧은/초단문 15일의 1× 및 160px 눈꽃 실루엣**은 개선했다고 보고했다. 하지만 사용자는 이 눈꽃이 아직 미적으로 충분하지 않다고 평가한다.

- **중앙 반경 28 근처가 비어** 눈꽃 결정이 하나로 연결되어 보이지 않음.
- 전체 디테일이 부족하고 **각 축의 일정 반지름 나선**이 여섯 개의 원통형 문자 다발을 붙여놓은 것처럼 보임.
- 목표는 여러 글자 나선이 **다른 반지름·위상·z 깊이에서 얽혀 하나의 정교한 결정**처럼 보이는 것.
- 첫날 U=1에서 총 슬롯 2개/정면 1글자, 동일 날짜 +2에 새 글자 0개 문제도 남음.
- DPR2 CPU1× 30fps 경계, 일부 미달 및 실기기 미검증.

**이번 작업은 최종 디자인을 완성해 실서비스에 올리는 것이 아니라, 조형의 시각적 개선과 성능 가능성을 비교하는 개발 전용 연구다.**

## 2. 다음 개발 실험

**새 개발 페이지** \`/__dev/sculptural-snowflake-study\`에서 아래 네 시안을 같은 fixture, 같은 글자 출처와 시간 기준으로 비교해.

- **D0(기존 G2):** 15일 기본/초단문에서 이미 눈꽃으로 인지되는 배치. 원본 변경 금지.
- **D1(중앙/접합부):** D0의 실제 원문 글자를 재배치해 중앙의 비어 보이는 공간에 **작은 육각형 문자 코어**, 큰 줄기-작은 가지 연결부 개선. 중심을 그냥 글자 덩어리로 채우지 말고 정돈된 음영과 작은 여백을 남길 것.
- **D2(교차/가변 반지름):** D1 위에 한 축의 여러 나선 트랙마다 서로 다른 **연속적인 \`r(s)\` 변화, phase, 깊이 좌표** 적용. 대칭적인 여섯 큰 줄기는 유지하면서 여러 실제 문장/echo 구절이 물리적으로 겹쳐 3D 입체 결정 느낌을 만드는지 확인. 독립된 원통 6개/무작위 글자 흩뿌리기가 되면 실패로 보고.
- **D3(빛 연구):** D2 **동일 글자 배치와 동일 시간**에 C2라는 깊이 기반 명도 변화를 추가. 기존 B(회전+부유), C0(밝아짐), C1(어두워졌다 복귀)은 그대로 비교 조건으로 남길 것. C2는 앞쪽으로 돌아 나오는 글자 자체가 은은히 빛을 받는 변화만; **별·글로우·투명 리본·그래픽 선·가짜 원문 추가 금지**.

지난번 생성된 예시 눈꽃 이미지는 *미적 목표를 설명하는 콘셉트*이지 구조를 무조건 똑같이 흉내낼 구현 명세가 아니다. 실제 작품을 구성하는 픽셀은 **출처가 분명한 일기 글자**여야 한다.

**디자인 작업 순서 준수:** D0 성능/정지 기준 → D1 중앙 코어 정지 검수 → D2 가변 반지름·교차 정지/회전 검수 → 1일 씨앗 별도 비교 → D3 반짝임 → 성능·QA. D1 정지 미감이 실패하면 실패를 보고하고 D2로 문제를 감추지 마.

## 3. 1일차 씨앗 별도 검증 (정책 무단 변경 금지)

- **S0:** 기존 G2 = 1일 열린 영역에 2슬롯/정면 1글자.
- **S1:** 유효 날짜 **1일 = 전역 높이 1/15 유지**. 아래쪽 열린 영역만 재조형/가지 추가/나선 슬롯 추가하여 더 분명한 작은 조각을 만드는 실험. 새 일기 첫 글자와 같은 날 추가 때도 가시 변화가 있는지 확인.
- **S2:** **비선형 첫날 리빌** 대조 실험. 현재 선형 1/15 규칙에서 벗어나므로 **사용자 승인 전 실제 제품 정책으로 절대 채택하지 마**. 실제 높이 증가량을 정확히 보고.
- 향후 초단문·첫날에서 물리적 수용량이 작아 추가일기 가시 변화가 없으면 명확히 FAIL로 보고. 눈꽃 중앙이나 미래 높이를 몰래 보여주지 마.

## 4. 기존 데이터/성장/가림 정책 보존

- Gate 2C의 anchor/echo 구분, 각 entryId/sourceSpan/copyIndex, 자연스러운 구절 반복, 고정된 anchor 배치와 미래 슬롯 ledger를 유지.
- 같은 날짜 다중 일기는 U 증가 0, 미래 글자 공개는 새 고유 날짜에만. 0일 미표시, 이전 일기 수정/삭제·어제 작성에도 기존 anchor 위치 안정성 확인.
- 눈꽃 전체는 돌지 않고 각 axis/작은 가지의 local helix만 천천히 회전. 실제 깊이/occlusion, 180° 반전 글자 0, 반쪽 글자 0, 미래 ghost 0.
- D0/D1/D2 성능/미감 비교 시 **글자 총수·실제 화면에 그린 글자 수·중심 인접 글자 수·echo 이동량**을 반드시 명시. D2가 더 예쁘지만 더 느리면 그 차이를 감추지 마.
- 대표 나선의 원문 길이 상한 24자, echo 상한 640자, 중심 반경 28 등의 기존 수치는 최종 제품 값으로 확정하지 마. 디자인 검수에 필요한 한도에서만 변경 후보를 실험.
- \`prefers-reduced-motion\`과 앱 움직임 줄이기는 자동 모션 정지. 도감 160px은 정적 렌더 우선.

## 5. 성능과 테스트

- 모바일 375×812, DPR1/2, CPU1×, Chromium headless 단일 작품·10초×3회, 필요한 경우 CPU4× 참고 측정. 영상 오프라인 렌더는 **실시간 FPS 아님**.
- 원문/echo/slot 안정, 글자 중복 출처, 0/1/3/5/8/15일, 같은 날 +2, 수정/삭제/과거 날짜 추가, 0/45/90/180° 가림, D3 vs D2 geometry 동일, reduced motion 재현성 검사.
- 375px DPR2에서 단일 작품 **CPU1× median 30fps 이상**을 1차 성능 기준, 60fps 지향. 반복 회차의 30fps 미달, 렌더링 끊김, 가시 glyph 감소, C2 과한 깜빡임, 중앙 과밀/육각형 실패를 분리 보고.
- 렌더 최적화 후보로 glyph atlas/비트맵 캐시/깊이 정렬 캐시/과잉 drawImage culling 등 측정 기반 1~2개 연구. 결과 없는 낙관적인 최적화 주장 금지.
- 실제 Android/iOS 앱인토스 WebView에 접근할 수 없으면 **실기기 미검증**으로 표시하고 재현 가능한 기기 테스트 절차를 남겨.
- 기존 \`glyphLayout.ts:193\` 및 Windows \`check:syntax\` 실패는 현재 재현 여부를 확인해 신규 이슈와 구분. 본 Gate의 관계 없는 코드 수정 금지.
