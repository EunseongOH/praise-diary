## 2. 작업 목적

기존 Gate 2A `/__dev/multi-helix-study`에서 **한 줄기를 나선형으로 감는 다중 일기 원문**은 그대로 유지하되, 단순 회전 위에 스노우볼의 눈가루 같은 미세 부유·은은한 문자 자체의 shimmer를 더한 모션을 비교하는 **개발 전용 실험**을 만들어 줘.

- **A** = 기존 회전만.
- **B** = A와 동일한 회전 + 글자 자체의 미세 부유.
- **C** = B와 동일한 회전/부유 + 일부 보이는 글자의 약한 밝기 shimmer.

세 안의 나선 기하/실제 원문/위치/성장/깊이 가림/폰트/기본 색/회전 clock은 완전히 같아야 해. B와 C를 유리하게 만들기 위해 빛/입자/그림자/새 UI를 추가하면 안 돼.

## 4. 상세 모션 구현

명세 21의 **§1~§4**를 반드시 따라 줘. 핵심 요구는 다음과 같아.

- A/B/C 각도·카메라·회전 속도·시계 동기화. 시안 기본 20초/회전, 느림 24초/회전은 미적 실험 출발값.
- 부유는 각 글자를 나선에 결속한 채 작은 연속 함수로 움직여. 화면상 ±0.3~0.7 SVG 좌표 단위 수준의 아주 작은 진폭부터 비교하고, 글자별 매 프레임 랜덤 지터를 만들지 마. 같은 일기 연속 글자는 대체로 함께 움직이도록 해.
- C의 shimmer는 **실제로 보이는 앞쪽 글자 일부(약 3~6%)**만 1.8~3.2초간 부드럽게 조금 밝아졌다가 돌아오는 효과로 구현. 별도 점, 별, 글로우, 블룸, 네온, 밝은 스파크를 추가하지 마. 가려진 글자를 반짝이게 노출하지 마.
- 숨겨진 글자가 회전해서 앞으로 나오는 2.5D의 실제 가림과 한글 문자 독해를 보존해. 같은 글자를 앞뒤로 복제하는 그림자 금지.
- `prefers-reduced-motion`에선 반복 모션 정지. pause/resume, 고정 t 캡처, 개발용 시간 컨트롤에서 위상 점프·메모리 누수 없어야 해.
- 성장 경계 위쪽 글자, 반 잘린 글자, 무작위 신규 텍스트 등 Gate 2A 회귀를 발생시키지 마.

## 5. 성능이 부족하다는 사실을 우선 전제로 작업

이전 보고에서 Canvas2D Gate 2A는 저사양 가정 CPU4×의 중간 S 8일 20.2fps, 긴 R15일+2는 2.3fps 수준이었어(실기기 측정 아님). **이미 느린 상태에서 효과를 추가하는 작업**이므로 시안을 구현하기 전 기준 측정값을 확인하고, 먼저 단일 clock/배치 캐시/글리프 캐시를 설계해.

- 매 프레임 React가 모든 글자에 대한 state를 만들거나 SVG/DOM 순서를 바꾸는 구현 금지.
- 같은 시계·같은 가상 데이터·같은 그린 글자 수 조건에서 A/B/C를 개별/동시 비교해.
- `375×812`, CPU 1×/4×, 10초×3회. FPS, p95, >33ms 프레임 수, Layout/Paint/Scripting, 실제 그린 글자 수, 캐시 갱신 횟수를 보고해.
- **B/C의 A 대비 프레임 p95 악화 10% 이내**는 연구 목표지 자동 통과 기준 아님. 현재 2A 렌더러 자체가 기준 미달이라는 사실을 숨기지 마.
- 오프라인 합성 영상과 브라우저 실시간 성능을 **반드시 분리**해 보고. GPU 없는 Chromium의 4× 측정 오차도 표시해.
- WebGL2 도입은 이 단계의 의무가 아니야. 실기기 성능 필요성과 구현 비용을 보고하되 임의로 상용 렌더러 선택 금지.
