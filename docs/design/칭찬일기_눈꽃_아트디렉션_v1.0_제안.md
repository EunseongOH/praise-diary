## 0. 핵심 콘셉트
**먼 곳에서는 눈꽃, 가까이에서는 내가 쓴 말.**

- [확정] 눈꽃은 사용자가 쓴 글자를 재료로 한다. AI가 문장을 만들어 추가하지 않는다.
- [확정] 눈꽃/글자들은 배경 전체에 자연스럽게 놓인다. 별도 아트 카드, 테두리, 그림자, 과한 글로우를 쓰지 않는다.
- [확정] 서로 다른 날짜의 첫 글은 월간 성장 높이를 한 단계 올린다. 같은 날짜의 추가 글은 높이는 그대로 두고 내부를 채운다.
- [확정] 일반 월은 15일에 완성. 2026년 12월의 특별 목표는 실제 출시일 이후 확정하기로 했으며 숫자를 임의로 채우지 않는다.
- [확정] 그래픽 상세에서는 사용자 선택에 따라 핀치 확대·이동. 확대·축소 버튼, 배율 표시, 제스처 안내 문구는 노출하지 않는다.
- [확정] 저시력 접근성, 움직임 줄이기, 실제 원문에 접근할 수 있는 독립적인 일기 목록 경로를 유지한다.
- [제안] 눈꽃은 기하학적으로 정돈된 6중 대칭 위에 글자 형태·자간·미세 회전의 유기적 차이를 얹는 **절제된 타이포그래픽 결정**으로 표현한다. 'AI 생성 일러스트'처럼 빛·색·장식을 많이 더하지 않는다.

## 1. 정지된 눈꽃의 실루엣과 구조

### 1.1 실루엣 [제안]
- 중심 결절 1개, 방사형 큰 줄기 6개(60도 간격), 큰 줄기당 좌우로 3쌍의 작은 가지. 현재 42개 구조 그룹을 1차 비교 기준으로 사용하되, **가지 수를 최종 확정으로 간주하지 않는다**.
- 6중 대칭은 유지. 완전히 동일한 자모 반복 대신 가지별 문자 길이와 미세 간격을 달리하여 자연스러운 결정감을 만든다.
- 정지 상태/축소 상태에서도 '눈꽃'으로 인지될 것. 텍스트가 제멋대로 퍼진 별무늬나 입자 구름으로 보이면 실패.
- 미표시 영역의 윤곽선과 '아직 채워지지 않은 가지'를 유령처럼 그리지 않는다.
- **[시각 검증 필요]** 순수 글자만으로 줄기 형태를 만들지, 접합부에 최소한의 비문자 미세 획을 허용할지는 정지 시안을 비교해 결정한다. 기본 제안은 순수 글자 우선.

### 1.2 글자 두께·밀도·크기 [시안 출발값 — 시각 검증 필요]
- 현재 340×340 SVG 좌표계를 1차 기준으로 삼되, 필요하면 최종 벡터 원화에 맞춰 수정한다.
- **독해 레이어:** 원본 문자 순서를 보존한 6.8~8.2 SVG 단위의 글자, 진행 방향의 평균 글자 간격 8~10단위. 1×에서는 눈꽃 질감, 2~3.2×에서는 일부 글자를 식별하게 하는 출발값.
- **결정 질감 레이어:** 글자 조각/중복 사용을 허용하되 원문에서 추출한 글자만 사용. 독해 레이어보다 작고 절제된 농도로 표현. 산만한 랜덤 점·별·가짜 문장 금지.
- 바깥쪽 끝은 조금 성기게, 줄기 접합부는 조금 촘촘하게. 중심은 겹침을 제한해 진한 덩어리로 뭉개지지 않게 한다.
- 축소판(도감 2열)은 글자 자체의 판독보다 **실루엣 인식**이 우선. 별도 인쇄용 문장 오버레이를 덧붙이지 않는다.
- 색조는 현재 임시 시안 그대로 유지한다. 최종 색/명도/대비는 별도 시각 검수에서 결정.

## 2. '한 편의 일기 = 한 흐름' 배치

### 2.1 원칙 [확정 + 설계 확장]
- [확정] 같은 일기의 글자들은 가까운 위치에서 이어져야 한다. 확대했을 때 적어도 일부가 **원문 순서대로** 읽혀야 한다.
- [제안] 일기마다 `reading lane`(일기 전용 문자 경로)을 하나 이상 배정한다. 경로는 눈꽃의 줄기·가지의 방향을 따라가고, 한 문장의 글자를 섞지 않은 **연속한 구간**으로 놓는다.
- [제안] 짧은 구절은 가능한 한 하나의 줄기/가지에서 읽히도록 한다. 길이 때문에 다음 가지로 넘어가야 한다면 물리적으로 연결된 이웃 가지를 사용하고 읽기 방향이 바뀌는 지점에는 간격을 준다. 눈꽃 반대편으로 갑자기 건너뛰는 배치는 금지.
- [제안] 글자 자체의 회전각은 해당 경로 접선을 따른다. 글자들이 통째로 거꾸로 읽히는 방향이 되지 않도록 읽기 방향과 문자 회전을 보정한다. 서체의 가독성이 깨질 정도의 수직 글자 회전은 금지.
- [제안] 독해 레이어의 공백·문장부호는 독해를 위한 간격/문자에 반영한다. 기존처럼 단순히 한글·영문·숫자만 남겨 모든 띄어쓰기를 없애면 읽기 경험을 만족하지 못하므로 수정 대상.

### 2.2 텍스트 선택 [제안]
- 한 일기의 500자 전체를 작은 눈꽃에 억지로 모두 넣지 않는다. 원문 중 **사용자가 작성한 연속된 구절**을 표시한다. 요약·의역·AI 재작성 금지.
- 초기 비교 시 한 일기당 대략 8~16자 내외의 연속 구절을 기본 검토 단위로 사용한다. 실제 길이와 글자 수·공간에 따라 달라질 수 있고 최종 고정값은 아님.
- 너무 짧은 일기는 글자를 반복해 시각적 결을 낼 수 있으나, 반복 부분이 새로운 문장처럼 오해되거나 본문을 왜곡해서는 안 된다.
- 원문 전체를 읽는 정식 경로는 기존 `이달의 칭찬 보기` → 일기 목록/상세이며, 아트 그래픽 자체에 불필요한 원문 모달/버튼을 추가하지 않는다.
- 확대해서도 언제나 모든 일기의 완전한 본문을 읽을 수 있다고 보장하지 않는다. 목표는 **일부 구절의 발견**과 **원문 상세 조회 가능성**이다.

### 2.3 데이터·슬롯 안정성 [설계 구현 조건]
- 일기 `entry_id`를 글자 그룹의 고유 ID로 사용한다. 같은 일기의 원문 순서 `grapheme_index`와 경로 `lane_id`, 슬롯 `slot_id`를 연결한다.
- 새로운 일기 저장 시 기존 일기의 위치·문자 순서가 전체 재배치되지 않아야 한다. 기존 슬롯 할당을 가능한 한 유지하고 **신규 슬롯만 점유**한다.
- 같은 날 추가하는 글은 **현재 표시 중인 높이 내부**의 비어 있는 문자 경로/밀도 레이어를 사용한다.
- 일기 수정 시 해당 일기 경로만 부분 재배치한다. 다른 일기의 위치는 가능한 한 고정한다.
- 마지막 한 편을 삭제하여 작성일 수가 감소하는 경우 높이 축소가 우선이므로 일부 경로 재배치가 불가피할 수 있다. 이 경우 자연스러운 변화 모션을 사용하며, 남아 있는 일기가 모두 그래픽에서 사라지지 않도록 예외 처리가 필요하다.
- 브라우저·세션을 바꾸어도 같은 월/기록이면 같은 배치가 나와야 한다. 연도-월, 그래픽 버전, 안정적인 entry_id/seed 기반으로 결정적으로 재구성하고 렌더 중 `Math.random()`을 호출하지 않는다.
- 오버플로우(15일을 넘어 같은 날 수십 편 등)에서 모든 글자가 보이는 것은 보장하지 않되, 새 글이 저장·조회되고 그래픽에서 표현 가능한 범위 안에 들어가도록 밀도 제한 정책을 둔다.

### 2.4 현 코드 대비 핵심 변경점
- 현 `assignDiaryGlyphs`의 전역 y/x 정렬은 같은 일기를 **논리적 인접 슬롯**에 할당하지만, 실제로는 서로 다른 줄기를 건너뛸 수 있다.
- 현 `extractDiaryGlyphs`는 문장부호와 공백을 버려 '원문으로 읽히는 느낌'을 손상시킨다.
- 현 `glyphForSlot` 대체 문자와 `letterCount` 변화에 따른 전역 슬롯 재분배는 새 일기 작성 시 이전 글자의 고정성을 약화시킬 수 있다.
- **개선 제안:** 전역 좌표 정렬이 아니라 눈꽃 그래프에서 연결된 `lane` 기반으로 할당하고, 읽기 레이어와 질감 레이어의 역할을 분리한다.

## 3. 날짜별 성장 (아래에서 위로)

| 상태 | 화면에서 보여야 할 것 | 금지사항 |
|---|---|---|
| 0일 | 눈꽃의 전체 외곽과 글자 없음. 별도 홈 카피는 기존 명세 준수 | 완성 눈꽃의 희미한 실루엣 |
| 1일 | 눈꽃 아래쪽에서 기록의 첫 작은 가지/조각이 생김. 글자 수가 짧아도 의도적인 시작으로 보임 | 완성 윤곽이 한 번에 나타남 |
| 5일 | 아래쪽이 명확하게 생겼고 그 위는 비어 있음 | 진행률 수치/대형 게이지 |
| 8일 | 중심부에 접근하는 결정 구조를 읽을 수 있음. 일부 이전 일기의 글도 나타남 | 읽기 구절이 서로 뒤엉킴 |
| 15일(일반 월) | 설계한 눈꽃 실루엣이 완성. 추가 글은 높이를 늘리지 않고 내부 밀도 변화 | 계속 높이가 무한히 증가 |
| 날짜 마지막 일기 삭제 | 해당 작성일 수 -1, 눈꽃 상단 일부가 천천히 사라짐 | 다른 글 전체가 갑자기 순간 이동 |

- **[확정]** 일반 월 15일. 12월의 예외 목표 미결정.
- **[제안]** 모양의 아래쪽부터 보인다는 감각은 유지하되, 단순 수평 마스크로 경로 중간이 덩그러니 잘려 보일 때는 **경로 접합 순서**를 고려한 점진적 노출로 다듬는다. 단, 새 표시 부위가 위쪽에서 먼저 나타나면 안 된다.
- **[제안]** 초기 1~2일에는 억지로 많은 글자를 넣어 눈꽃 절반을 미리 완성하지 않는다. 이 단계에서 긴 구절이 다 읽히지 않는 것은 정상이며, 성장과 함께 일부 글자가 더 보일 수 있다.

## 4. 미세 모션: 구조에 매달린 글자

| 부분 | 방향·기준축 | 출발 모션 값(최종 미확정) |
|---|---|---|
| 큰 줄기 | 중심/결절에 고정, 전체 방사 방향 유지 | ±0.2~0.5°, 8~12초 왕복 |
| 작은 가지 | 해당 줄기와 만나는 접합점 기준 국소 회전 | ±0.5~1.1°, 6~10초 왕복 |
| 중심부 | 거의 고정 | 0~0.15° 또는 정지 |
| 끝 글자 | 가지와 같은 모션에 따라 움직임 | 글자 자체의 독립 랜덤 떨림 없음 |

- **[확정]** 서로 다른 큰 줄기와 가지는 서로 다른 회전축/위상을 갖는다. `Math.random()`으로 프레임마다 진동시키지 않는다.
- **[제안]** 첫 저장 성장 모션은 대략 0.8~1.2초를 출발값으로 비교. 새 글자의 등장과 접합이 끝나면 미세 모션으로 돌아간다.
- **[제안]** 사용자가 핀치 확대해 글자를 읽는 동안에는 반복 모션을 잠시 정지한다. 축소하면 자연스럽게 재개하되 글자가 갑자기 튀지 않게 한다.
- **[확정]** 도감 축소판, `prefers-reduced-motion`, 앱의 움직임 줄이기 설정에서는 모션 없이 정적 작품 제공.
- 화려한 파티클 분출, 밝기 점멸, 강한 글로우, 전체 눈꽃 회전은 제안하지 않는다.

## 5. 확대 감상 UX와 마이크로카피

### 동작 [확정]
- 홈/월별 상세에서 그래픽을 탭하면 기존 그래픽 감상 화면으로 이동.
- 그래픽 감상 화면 기본 배율 1×. 두 손가락 핀치 확대/축소와 확대 중 한 손가락 이동.
- 확대 버튼, 배율 표시, 도움말 배너, 제스처 온보딩 없음.
- 확대하지 않아도 그래픽 감상과 `이달의 칭찬 보기`(원문 목록)가 가능.

### 표현 [제안]
- 1×: 글자는 눈꽃을 이루는 질감, 완성된 실루엣이 먼저 읽힘.
- 2~3.2×: 일부 실제 일기의 **연속한 원문 구절**을 순서대로 발견할 수 있음. 색·굵기 하이라이트로 특정 일기를 선택하도록 유도하지 않음.
- 확대 중에는 글자 판독을 위해 미세 모션을 잠시 멈춤.

### UX Writing: 신규 노출 문구 추가 없음
- 화면 제목은 기존 월별 그래픽 제목을 유지.
- 월별 기록 수 표기는 기존 `N일의 칭찬`을 유지.
- 하단의 원문 이동 행동은 기존 `이달의 칭찬 보기`를 유지.
- **삭제/비노출:** `그래픽을 확대해 보세요`, `핀치해서 읽어보세요`, `+ / -`, 배율 표시 등의 화면 문구/컨트롤.
- **[추가 제안]** 현재 홈 화면의 `그래픽을 누르면 크게 볼 수 있어요.` 역시 감상 화면 이동이라는 낮은 우선순위 기능을 반복 안내하므로 제거하는 편이 자연스럽다. 홈의 주요 문구는 월별 제목·기록 수·일기 CTA 정도만 유지한다. 최종 삭제는 사용자 검토 후 확정.
- [제안, 필요 시에만] 그래픽 불러오기 실패 상태: `그래픽을 잠시 보여드리지 못하고 있어요. 남긴 칭찬은 그대로 있어요.` + `다시 보기`. 이 오류 복구 UI의 필요성은 기능 안정성 설계 후 결정한다.

## 6. 타이포그래피와 대비
- UI 제목/본문은 기존 SUIT Variable 후보 및 공통 타이포 토큰을 유지. **그래픽 안의 글자에는 같은 서체를 쓰되 크기·자간·회전·농도를 별도 아트 토큰으로 관리**한다.
- 독해 레이어의 글자끼리 겹치지 않게 하고, 글자 위에 다른 장식선을 덧칠하지 않는다.
- 의미 있는 원문 구절이 읽히는 확대 상태에서는 충분한 텍스트 대비를 보장해야 한다. 최종 색상이 결정되면 4.5:1을 검토한다.
- 장식 레이어와 독해 레이어의 불투명도 역할을 구분. 대비 기준을 통과하기 위해 과도한 글로우나 채도를 높이는 방법을 쓰지 않는다.
- 화면 전체 한 배경 유지. 아트만 다른 색의 카드로 감싸는 패턴 금지.
- SVG 글자 그룹은 스크린리더에서 원문이 중복 낭독되지 않게 하고, 접근 가능한 월/상태 레이블과 원문 목록 경로를 별도로 제공.
- 데이터는 인증된 사용자 화면에서만 사용. 자동 공유·로그·분석 이벤트에 원문/개별 glyph mapping을 전송하지 않는다.

## 7. 정지 시안 3종 검수 방법

**[시안 A — 우선 추천] 순수 문자 결정**: 큰 줄기와 가지를 전부 문자로 구성. 원근감/색 장식 최소화. 확대 읽기 경로가 통과하면 최우선 채택.

**[시안 B — 보조 비교] 문자 + 최소한의 접합 획**: 정지 상태에서 접합부가 너무 끊겨 눈꽃으로 인지되지 않을 때만 짧고 가는 연결 획을 추가. 전체 외곽선 금지.

**[시안 C — 보류] 문자가 그림 위에 얹힌 형태**: 완성된 눈꽃 모양에 랜덤 텍스트를 채우는 방식. 이미지+텍스트가 분리되어 보여 기본적으로 비추천.

**제출해야 할 시안(같은 폰트·같은 임시 색 사용):** 0·1·5·8·15일, 매일 한 편 기준 / 동일 날짜에 추가 일기 3편 / 아주 짧은 일기(2~3글자) / 300자 이상 일기 / 확대 1×·2×·3.2×. 정지 이미지로 먼저 검토하고, 정지 시안 확정 후 모션 비교.

## 8. 디자인 QA / 수용 기준 (정량 수치는 출발 목표)

- [ ] 320px 모바일에서도 15일 완성 그래픽을 **눈꽃**으로 인지한다. 5명 간단한 관찰에서 4명 이상 바로 구분하는지 가벼운 사용성 확인을 추천한다(통계적 검증 아님).
- [ ] 기본 화면에서 완성 윤곽 미리보기, 별도 그래픽 카드, 과장된 광원 효과가 없다.
- [ ] 1·5·8일의 성장 경계가 확실히 아래→위로 이동한다.
- [ ] 2~3.2× 확대 시 샘플 일기 몇 편에서 공백/순서를 유지한 **실제 연속 구절 4~10글자** 정도가 읽힌다(일기 길이와 성장 상태에 따라 변함, 사용성 목표이지 보장값 아님).
- [ ] 한 일기의 구절이 눈꽃 반대편으로 불연속 점프하거나 다른 일기와 교차 삽입되지 않는다.
- [ ] 동일 데이터 재방문/기기 재진입 시 글자들의 위치가 불필요하게 바뀌지 않는다.
- [ ] 같은 날짜 글 추가로 높이가 높아지지 않는다. 새 날짜 첫 일기에서만 높이가 달라진다.
- [ ] 수정/삭제 시 영향을 받지 않은 다른 일기의 글자는 가능한 한 같은 위치에 남는다.
- [ ] 확대 중 글자와 줄기 모션이 방해되지 않는다. 축소 상태에서 모션을 끄면 정지 작품으로도 자연스럽다.
- [ ] 보이는 확대 버튼/배율/제스처 안내 문구가 없다. 원문 상세 경로는 유지된다.
- [ ] Android/iOS 웹뷰 핀치/스와이프/화면 회전/뒤로가기/저사양 기기 실제 검사 필요.
