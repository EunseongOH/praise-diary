## 1. 아트 디렉션의 전환 [확정]

- **눈꽃/월별 상징물의 형태를 먼저 설계**하고 사용자가 쓴 글자를 조형 재료로 배치한다. 기존의 '고정 나선 제작 → 여섯 갈래로 조립' 방식은 여러 원통을 억지로 붙인 것처럼 보이므로 유일한 제작 방식으로 삼지 않는다.
- 사용자가 앱에 들어왔을 때 **작품 자체가 아름다워 보이는 것**을 그래픽 안의 원문 독해보다 우선한다. 일기 전체 원문 열람은 별도의 일기 목록·상세 화면에서 지원한다.
- **글자 자체가 조형물**이다. 문자 크기·방향·밀도·층위·가림·깊이를 달리해 완성된 형상을 만든다. 별도 외곽 선화/비문자 그래픽으로 형태를 속이거나 원문에 없는 문장을 생성하지 않는다.
- **나선형 2.5D 회전은 여러 모션 중 하나로 보존**한다. 일부 문자는 정해진 축을 감으며 회전하고, 일부 문자는 제자리에서 미세하게 부유하고, 일부는 작품 안의 다른 위치로 이동해 다시 결정을 형성하는 데 참여할 수 있다.
- **전체 형태의 안정성 + 국소적 변화 허용.** 글자가 위치를 옮겨 눈꽃의 일부 형태·질감이 조금씩 달라지는 것은 괜찮지만, 멀리서 보거나 작은 도감에서 볼 때 **항상 여섯 갈래 눈꽃의 기본 실루엣**이 유지되어야 한다.
- 안정적인 '결정 구조층', 빈 곳을 메우고 겹침·깊이를 표현하는 '입체 질감층', 일부 글자가 다른 부위로 이동하는 '이동 글자층'이라는 **서로 다른 역할이 공존**할 수 있다. 모두 무작위로 떨거나 같은 경로에 묶일 필요는 없다.
- 눈꽃은 트리처럼 전 영역을 고르게 채우는 것이 아니라 **중앙 결정/여섯 큰 갈래/작은 가지/갈래 사이의 여백**이 함께 살아 있어야 한다. 글자가 과밀한 덩어리가 되지 않는 정교한 코어를 지향한다.
- 반짝임은 일률적인 점멸보다 **글자별 밝기와 깊이의 미세한 차이**를 활용한다. 이전 B(회전+부유), C0(밝아짐), C1(어두워졌다 복귀), C2(깊이 기반 밝기) 연구 방향은 보존하되 최종 조합은 보류.
- **다른 월별 그래픽에 재사용 가능한 방식**을 지향한다. 눈꽃에만 맞춘 42개의 고정 축/원통 배치가 일반 아트 엔진의 구조를 제한하지 않도록 한다.

## 2. 기존 제품/데이터 정책은 유지 [확정]

- **대표(anchor) 나선/구절**은 실제 일기 원문의 연속성을 어느 정도 보존하고 안정적으로 배치한다. 짧은 글도 아름답게 보이도록 **반복(echo) 나선/글자**에는 같은 원문의 자연스러운 일부 구절 재사용을 허용하며 entryId/source offset/copyIndex로 출처를 추적한다.
- 일부 **이동하는 글자는 우선 echo에서 선정**하는 방향으로 연구한다. 대표 원문과 다른 기록의 안정 슬롯은 불필요하게 이동시키지 않는다. 구체 비율은 아직 결정하지 않았다.
- **고유 작성일 수가 성장 높이를 결정**한다. 같은 날 여러 편은 높이를 늘리지 않고 열린 영역의 밀도/질감만 변화시킨다. 미래 성장 영역의 글자와 윤곽은 먼저 보이지 않는다. 삭제/수정 시 기존 안정 슬롯 규칙을 훼손하지 않는다.
- 전부가 움직이지 않더라도 정지 화면에서 아름다운 실루엣을 유지해야 한다. `prefers-reduced-motion`에서 자동 모션 정지. 160px 도감 타일은 정적인 구성을 우선한다.

## 3. 다음 시각 실험의 제안된 비교 틀 [실험 예정]

- **구조형:** 기존 고정 나선 조립을 넘어서 글자의 배치·방향·깊이 자체로 정교한 여섯 갈래 결정 실루엣을 만드는 정적 조형.
- **유동형:** 위 정적 조형을 기본으로 유지하면서 일부 echo 글자가 서로 다른 영역으로 이동·합류하는 버전. 글자 이동에 따라 일부 디테일이 바뀌어도 눈꽃 전체가 해체되어 보이면 실패.
- 먼저 **정지 작품의 아름다움**(375px/160px, 기본·짧은·초단문 일기, 중심/가지)을 비교한다. 다음으로 이동이 더해졌을 때 입체감·글자 출처·안정성·성능을 비교한다.
- 모션은 고정 구조/나선 2.5D 회전/미세 부유/영역 이동/밝기 변화를 분리해 평가한다. 움직임의 시간·궤도·비율·물리엔진 사용 여부·밝기 값은 미확정.
- 데이터·렌더링 아키텍처는 Shape / Typography / Motion 등의 **역할 분리 방향**을 검토하되, 실제 클래스/파일·라이브러리 확정은 로컬 엔진 분석 후 별도 구현 명세로 결정한다.
- 성능 문제를 잊지 않는다. Gate 2D에서 375px DPR2 CPU1× 30fps 이하 보고가 있었으므로 일부 글자만 이동하는 실험과 저비용 정지 폴백을 함께 검토한다. 실제 앱인토스 WebView 성능은 아직 미검증.

## 4. 아직 승인되지 않은 것 [보류]

- 글자 이동 비율/횟수/범위, 트리식 자유 입자 움직임을 어느 정도 도입할지, 독립된 파티클 렌더링 기술.
- 글자 크기·반지름/나선 수·코어 기하·최종 색·서체·글로우/반짝임 강도.
- 첫날 1/15 성장의 변경(S1/S2), 같은 날 포화 상태 처리, 렌더러 선택과 성능 폴백 임계값.
- Gate 2E의 구체 작업 지시와 제품 채택, 2026년 12월 특별 목표.

- 이 파일은 **사용자가 합의한 방향을 기록**한 것이며 최종 디자인이나 Gate 2E 구현이 끝났다는 뜻이 아니다.
- 참고자료 자체는 어떠한 저장소·Space에도 올리지 않는다. 이후에는 사용자와 합의한 새 결정 내용만 GitHub에 반영한다.
- 기존 Gate 2A~2D 소스와 `artifacts/`는 사용자 로컬에 미커밋된 상태이므로 보호한다. Claude Code는 `git status --short` → `git fetch` + `git show`로 원격 문서를 읽고, 무분별한 `git pull/reset/restore/clean/checkout` 금지.
- 실서비스 `GraphicArtwork`, 홈/작성/도감/상세 변경 및 구현 코드 commit/push/PR은 사용자 지시 전 금지. Claude Code 사용자 대상 보고는 한국어.
