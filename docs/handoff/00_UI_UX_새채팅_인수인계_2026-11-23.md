> **용도:** 이 문서 하나를 읽고 앱 전체의 UI/UX·화면별 플로우·UX Writing·디자인 시스템을 논의할 수 있도록 만든 **채팅 간 핸드오프**.

## A. 이 채팅과 다른 채팅의 역할 분담

- **기존 '그래픽 채팅':** 월별 상징 그래픽(특히 12월 눈꽃)의 실루엣, 타이포 나선, 2.5D 앞뒤 가림, 부유·반짝임, 날짜별 성장 알고리즘, 밀도 적응, 렌더링 성능 및 그래픽 예술성의 결정. **최신 연구는 Gate 2C**.
- **새 '앱 UI/UX 채팅' (이 문서의 대상):** IA, 홈 화면 정보 위계, 헤더·탭, 작성 폼, 회고 질문, 저장 후 피드백, 꺼내보기, 개별 기록 목록/상세, 월별 도감 레이아웃, 설정, 접근성, 반응형, 토스 미니앱 환경, UX Writing, 디자인 시스템.
- 새 채팅은 그래픽 **배치 엔진을 다시 설계하거나 임의로 실서비스에 적용하지 않는다**. UI에서 필요한 그림 크기/시각 영역/여백/성능 요건을 정하고 그래픽 채팅과 합의한다. 양쪽 공통 계약은 **월별 진행일 수, 월간 성장, 같은 날짜 추가, 2열 도감, 그래픽 무경계 배경, 확대 제스처**이다.
- 사용자는 ChatGPT와 기획/아트/UX를 논의하고, 코드는 **Claude Code**에 한국어 프롬프트로 구현을 맡는 협업 방식을 사용한다. 제품 디자인에 대한 사용자 승인 전 코드를 임의로 최종 확정하지 않는다.

## B. 서비스의 목적과 현재 실제 구현 수준

**칭찬일기 (Praise Diary)**: 자신이 하루에 잘한 일을 기록하면 월별 **자신의 문자를 재료로 한 상징 그래픽**이 아래에서 위로 자라고, 나중에 과거의 일기를 랜덤으로 다시 읽으면서 자신의 좋은 순간을 발견하는 앱. **앱인토스(Toss Mini App)** 출시 목표.

- **[확정]** 그래픽이 홈의 주인공이며 큰 일수 차트/진행 바, 수많은 상태 배지/카드·과장된 AI 응원 문구는 지양.
- **[현황]** GitHub의 UI 앱은 React 18 + TypeScript + Vite 프로토타입. \`README.md\`와 \`docs/IMPLEMENTATION_STATUS.md\` 기준 저장 데이터는 **sessionStorage와 가상 예시**; 정식 인증·DB·앱인토스 SDK·알림 발송 구현이 완료된 앱이 아님.
- **[현황 / 주의]** 그래픽 연구 Gate 2A~Gate 2B는 사용자가 Windows PC의 **로컬 미커밋 파일**로 Claude Code를 통해 만들었고, Gate 2C의 **설계 명세와 구현 프롬프트만 GitHub에 커밋**됨. 원격 GitHub만 열어 '현재 최신 그래픽 실험 코드'가 전부 존재한다고 주장하지 말 것.
- **[현황]** 별도 그래픽 연구 페이지들을 아직 실서비스 \`GraphicArtwork\`로 교체하지 않음.
- **[주의]** 과거 \`docs/IMPLEMENTATION_STATUS.md\`와 \`README.md\`에 남은 설치·빌드 미실행/미검증 설명은 작성 당시 기록. 사용자가 전달한 최신 Claude Code 보고에는 \`src/graphics/glyphLayout.ts:193\` 타입 오류 및 Windows \`check:syntax\` 경로 오류가 있었음. 새 채팅이 현재 상태를 판단하려면 실제 로컬/CI를 다시 확인해야 한다.

## C. 핵심 제품 정책 [확정]

| 주제 | 확정 내용 |
|---|---|
| 일기 작성 | 같은 서비스 날짜에 **여러 편 작성 가능**. |
| 월간 진행 | 해당 월 유효한 일기의 \`entry_date\` **고유 날짜 수**만 성장 일수로 계산. 같은 날 2편이어도 1일 인정. |
| 작성 날짜 | 기본 KST 자정(00:00) 경계. 사용자가 하루가 바뀌는 시각을 설정에서 바꿀 수 있음(구체 선택지는 제안). 신규 기록의 기본은 서비스 날짜 '오늘', 선택 가능 날짜는 '어제'. |
| 날짜 혼동 방지 | 작성 화면 **상단에 실제 귀속 날짜 상시 표시**. 작성 중 하루가 바뀌어도 본문/선택 날짜 유지, 유예 저장을 지원할 방향 확정(유예 종료 기한은 미정). 설정 변경은 과거 \`entry_date\`를 소급하지 않음. |
| 질문 | 본문 입력 전에 회고 질문 2개를 제공하되 **질문을 선택하지 않고도 자유롭게 작성 가능**. 질문 내부 유형명은 UI에서 숨김. |
| 삭제 | 마지막 한 편이 제거되어 그 날짜 자체가 비면 그래픽 성장 일수 -1, 달별 영향 안내. 같은 날짜에 다른 글이 남으면 일수 유지·해당 글자만 제거. 전체 삭제는 다단계 확인. |
| 꺼내보기 | **개별 일기 10편을 최초 달성하면 영구 해제**. 같은 날짜 여러 편도 각각 센다. 한 번 해제되면 나중에 기록이 10편 아래로 줄어도 재잠기지 않음. 추첨은 개별 일기 \`entry_id\` 단위. |
| 원문 접근 | **전체 기록 목록·기록 수정·삭제는 꺼내보기 잠금과 무관하게 이용 가능**. 홈에서 별도 진입이 필요. |
| 도감 | **2열 월별 그래픽 카드**. 과거의 미완성 그래픽도 보관/감상, 미래 미공개 월은 잠금. 미래 월 제안 액션은 잠금 안내 안의 낮은 위계. |
| 월별 테마 | 2026-12 눈꽃, 2027-01 붉은 양과 해. 2027-01 정규 목표 **서로 다른 15일**. **2026-12 특별 목표 일수 미확정**. |
| 미래 작성 | MVP는 새 일기의 작성일을 서비스 기준 오늘/어제로 제한. 미래 월 잠금 그래픽 상태에서 미래 기록 작성 플로우 없음. |
| 향후 확장 | 미래에는 한 달에 여러 테마 후보가 있다면 그달 첫 일기 작성 시 테마 선택 가능하도록 데이터 구조 고려. 현재 12월/1월 1개씩이라 선택 UI 없음. |
| 알림 | 알림 의도/문구는 설계됐으나 앱인토스 정책 검증/승인 전 알림 동의·발송 UI **기능 플래그 OFF**. |

**H-01 홈 [확정된 위계]:** 월/테마명 → **화면 중앙의 큰 월간 작품** → 작은 작성 인정일 수 → 가장 중요한 기록 작성 CTA → 네비게이션. 사용자가 오늘 이미 일기를 썼으면 **'칭찬 하나 더 남기기'**; 전이면 **'오늘의 칭찬 남기기'**. 그래픽 자체를 열어 감상할 수 있고, 홈에는 독립된 **'내가 남긴 칭찬 보기'**를 낮은 위계로 둠(위치·형식은 제안).

**D-01 작성:** 상단 실제 기록 귀속일/오늘·어제 선택. 본문 이전에 질문 2개(선택 사항); 선택/비선택 모두 저장 가능. 제목 선택 입력, 자동 임시 저장, 500자 상한 등은 **[제안/보류]**; 실제 저장 실패·시간 경계·키보드·모바일 스크롤이 UI 리뷰 대상.

**D-02 저장/완성:** 저장 성공 후에만 성공 메시지와 그래픽 변화를 보여줌. 새로운 작성일 = 높이 성장, 같은 날짜 추가 = 내부 글자 추가, 처음 목표 도달 = 월별 특별 완성 상태. 전월 '어제' 기록은 **전월** 그래픽부터 반영. UI는 기록 성공/실패를 확실히 전달해야 함.

**L-01~04:** L-01 잠금/첫 해제/빈 상태를 구분. L-02는 사용자 원문을 그대로 보여주고 '다른 칭찬 꺼내기' 가능. L-03는 날짜/월별 그룹 기록 목록(잠금과 무관). L-04는 기록 상세·수정·삭제 경고. **'꺼내보기'는 임시 이름**이므로 네이밍 변경 가능.

**C-01~04:** C-01 2열 카드 확정. C-02에서 원래 월의 그래픽과 해당 월 기록 확인. C-03 미래 테마 잠금 안내/낮은 위계의 의견 링크. 해당 월 제안 C-04는 장기 운영/스팸 처리 정책 미확정. 미래 그래픽이나 완성 에셋 미리 공개 금지.

**S-01 등:** 사용자의 하루 경계, 움직임 줄이기, 일기/데이터 삭제, 개인정보/안내. 알림 제안 UI는 **기능 플래그 OFF**를 유지. 하단 내비게이션은 **3탭(홈·꺼내보기·도감)+설정 별도 진입이 권장안**이지만 기존 4탭 후보가 있었고 **최종 미확정**. 새 채팅에서 사용자와 비교 검토.

## E. 디자인 시스템과 시각 방향

- **[확정] 그래픽 전용 카드 금지:** H-01·D-02·C-02·G-03에서 그래픽은 다른 배경의 둥근 모서리 카드/패널 안에 갇히지 않고 화면 전체와 **무경계로 이어져야 함**. 현재 비교 기본 배경은 다크 \`#0C1111\` (**시안**, 최종 브랜드 색 아님). 상단바·그래픽·버튼·하단 네비게이션이 조화로운 하나의 무대.
- **[후보] 컬러:** \`#B8D68A\`, \`#61AE72\`, \`#FFFFFF\`, \`#FAD89E\`, \`#A6C5D3\`. 대비가 부족할 수 있으므로 본문 색과 구분. 브랜드 팔레트는 **미확정**. 라이트 테마 검토 가능하나 '화이트 화면+어두운 아트 카드'로 되돌리지 않음.
- **[후보] 서체:** SUIT Variable 우선 시안, Pretendard Variable 비교. 폰트·굵기 최종 미정. 기존 UI 타이포 기준: 본문/사용자 일기 16px 이상, 제목·보조 텍스트는 \`design-system/typography.md\`와 \`src/styles/tokens.css\` 참고.
- **디자인 언어:** '기록을 쌓는 조용한 일기장'. 과한 카드형 대시보드·진행률 게이지·불필요한 카테고리 칩·AI풍 응원 문구·장식적 아이콘/그라데이션·불필요한 상단 제목 중복을 지양. 버튼/헤더/행/네비게이션 컴포넌트를 재사용.
- **접근성:** 주요 조작 44px 이상, 본문 대비 4.5:1, 중요 비텍스트 3:1, 키보드 포커스, 작은 화면/safe area, 줄바꿈, 스크린리더, \`prefers-reduced-motion\`, 사용자가 직접 수행하는 제스처의 접근 대체 입력. 실제 Android/iOS WebView 실기기 QA 필요.
- **UX Writing:** \`src/content/copy.ts\`가 카피 소스.  \`design-system/writing.md\` 확인 후 수정. 질문 유형/내부 연산 ID/AI가 만들어낸 문구를 사용자에게 노출하지 않음.

## F. 그래픽 채팅에서 결정된 **UI가 알아야 할 그래픽 계약** (세부 미학은 그래픽 채팅 전담)

1. 기본 제품 목표는 사용자가 앱에 들어왔을 때 **아름다운 월별 작품을 보게 하는 것**. 확대해서 모든 일기 원문을 읽는 것은 부차적. 원문 전체는 L-03/L-04에서 확인할 수 있어야 함.
2. 눈꽃은 6갈래 줄기와 작은 가지를 갖는 문자 기반 입체 결정. **각 줄기/가지 로컬 축**을 원문 글자가 연속된 나선으로 감싸며 천천히 회전. 실제 앞/뒤 가림, 글자의 미세 부유·은은한 밝기 변화를 실험 중.
3. **날짜별 성장**은 서로 다른 \`entry_date\` 수로만 증가. 같은 날 추가는 높이 유지·구성 글자 증가. 미래 영역의 글자는 좌표를 **미리 예약**하되 성장일이 그 영역을 열 때에만 공개. 글자 반쪽 노출/미래 ghost 금지.
4. 짧은 일기에서도 작품을 채우도록 **대표(anchor) 나선**은 원문 연속 구절의 독해 가능한 흔적을 보존하고, **echo 나선**은 실제 원문의 **자연스럽게 끊긴 일부 구절을 반복**하여 가지·외곽·부족한 밀도를 보강. 반복량은 조형에 따라 가변. 반복한 문구를 실제 기록 편수로 세지 않음.
5. **모션 시안은 미채택:** B=회전+부유, C0=B+약한 밝아짐, C1=B+은은한 어두워졌다 복귀. 최종 강도/선택 미확정. reduced-motion에선 정지.
6. **도감 160px 정지 타일**, 홈 큰 아트, 저장 후 성장, 확대 상세의 동일한 텍스트 기반 작품을 UI에서 잘 수용해야 함. 도감 카드마다 무거운 3D canvas를 동시에 돌리지 않고 정적/경량 대체 검토.
7. **확대 정책 [확정]:** G-03 기본 1×, 조작 버튼/배율 표기/가이드 문구 없는 **선택적 핀치(1.0~3.2×)+확대 후 팬**, 키보드 대체 입력. 확대 자체가 홈의 주요 안내가 되지 않음.
8. **상태:** Gate 2C 개발 전용 구현 명세는 GitHub에 최신으로 존재하지만 결과 코드·시각 채택은 아직 사용자에게 검수되지 않음. 다른 채팅에서 그래픽을 이미 완성·통합했다고 표현하지 말 것.

## I. 실무 협업 및 업데이트 규칙

- **기획·UI 리뷰**는 ChatGPT 대화에서 먼저. Claude Code에 전달할 때는 정확한 구현 계획·작업 경계·테스트·완료 기준을 **한국어 프롬프트**로 준다.
- 사용자의 로컬 Windows 저장소에는 **미커밋 그래픽 연구 파일이 많으므로, Claude Code가 \`git pull\`/checkout/reset/restore/clean을 무턱대고 실행하지 말 것**. 필요하면 \`git status --short\` → \`git fetch origin feat/design-system-prototype\` → \`git show origin/feat/design-system-prototype:<문서경로>\`를 사용. 문서 커밋이 자동으로 로컬에 들어오지는 않음.
- GitHub 리포지터리는 **공개**임. 실제 사용자의 일기 원문/접근 토큰/민감 데이터/글꼴 바이너리 업로드 금지.
- 새 채팅에서 UI를 수정하면 **UI 변경 문서와 결정 이력**을 별도로 추가하고 이 handoff의 '현재 결정 상태'와 최신 관련 링크를 갱신하면 이상적. 그래픽 채팅의 문서 20~23은 아트용 원본으로 유지.
- 이 문서의 목적인 '맥락 이관'은 **이전 대화를 새 채팅이 자동으로 전부 기억한다는 약속이 아님**. 새 채팅에서 이 파일을 GitHub 커넥터로 실제 열거나 사용자가 내용을 붙여넣어야 정확히 인수인계 가능.
